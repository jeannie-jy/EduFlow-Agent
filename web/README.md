# EduFlow Web Frontend

English | [简体中文](README.zh-CN.md)

The `web/` directory contains the EduFlow React frontend. The current deliverable is a frontend-only Dijkstra teaching workbench with a responsive graph, synchronized step playback, an inspector, and persistent light/dark themes.

## Requirements

- Node.js 20 or later
- npm 10 or later

## Install and run

From the repository root:

```bash
cd web
npm ci
npm run dev
```

Open the URL printed by Vite, normally `http://127.0.0.1:5173/`.

To expose the development server to another device on the same network:

```bash
npm run dev -- --host 0.0.0.0
```

## Quality checks

```bash
npm run typecheck
npm run test
npm run lint
npm run build
```

Run the complete verification gate with:

```bash
npm run verify
```

`verify` runs type checking, all Vitest tests, and the production build. Lint is kept as a separate command so warnings remain visible.

## Current architecture

```text
src/
├─ app/                    routing and application providers
├─ components/
│  ├─ brand/               EduFlow brand assets
│  ├─ effects/             optional decorative effects
│  ├─ layout/              application shell and sidebar
│  ├─ ui/                  shared Shadcn/Base UI primitives
│  └─ workbench/           Dijkstra workbench and simulation model
├─ pages/                  route-level states
├─ test/                   shared test setup
└─ theme/                  persistent light/dark theme support
```

The Dijkstra demonstration is generated by a local deterministic model. There is currently no backend request, authentication, project persistence, or AI generation API.

## Theme behavior

- Light theme is the default.
- The selected theme is persisted in local storage.
- Theme switching does not reset the current route or simulation frame.
- New colors should use semantic CSS variables from `src/styles/globals.css` rather than hard-coded values.

## Mock boundary

Local simulation frames are intentional demo data, not an API mock server. When backend integration starts, keep API contracts and transport code outside React components and preserve the local model as a development fallback and deterministic test fixture.
