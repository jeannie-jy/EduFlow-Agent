# EduFlow Web Frontend

English | [简体中文](README.zh-CN.md)

The `web/` directory contains the EduFlow React frontend. The current deliverable includes a Dijkstra teaching workbench with responsive graph, synchronized step playback, inspector panels, persistent light/dark themes, and a full API service layer connecting to the FastAPI backend.

## Requirements

- Node.js 20 or later
- npm 10 or later

## Install and run

From the repository root:

```bash
cd web
npm ci
npm run dev
```

Open the URL printed by Vite, normally `http://127.0.0.1:5173/`.

To expose the development server to another device on the same network:

```bash
npm run dev -- --host 0.0.0.0
```

For the full stack experience, start the backend as well:

```bash
# From repository root
./start.sh          # Linux/macOS
.\start.ps1         # Windows
```

## Quality checks

```bash
npm run typecheck    # TypeScript type checking
npm run test         # Vitest (80 tests)
npm run lint         # oxlint
npm run build        # Production build
```

Run the complete verification gate with:

```bash
npm run verify
```

## Current architecture

```text
src/
├─ app/                    routing (11 routes) and application providers
├─ components/
│  ├─ brand/               EduFlow brand assets
│  ├─ effects/             optional decorative effects
│  ├─ layout/              application shell and sidebar
│  ├─ ui/                  shared Shadcn/Base UI primitives (25+ components)
│  ├─ workbench/           workbench simulation models and visualizations
│  │   └─ visual-objects/  DSL visual object renderers (Array/Table/CodeBlock)
│  ├─ FileUploader.tsx      drag-and-drop file upload with topic extraction
│  ├─ FeedbackPanel.tsx     frame-level feedback: rating/correction/suggestion
│  ├─ KnowledgeCard.tsx     concept knowledge card component
│  └─ MindmapView.tsx       concept relationship tree visualization
├─ features/               Auth (Login/Register) and Landing page
├─ pages/                  11 route-level page components
├─ services/               API client, SSE connection, 8 service modules
├─ test/                   shared test setup and MSW mock handlers
└─ theme/                  persistent light/dark theme system
```

The Dijkstra demonstration is generated by a local deterministic model and serves as both the default workbench experience and a fallback when the backend is unavailable.

## Backend integration

The `services/` directory provides a complete API layer connecting to the FastAPI backend:

| Service | Endpoints |
|---------|-----------|
| `projects.ts` | `POST /api/projects`, `GET /api/projects`, `GET /api/projects/{id}` |
| `generate.ts` | `POST /api/projects/{id}/generate`, SSE stream, `POST /regenerate` |
| `frames.ts` | `GET /api/projects/{id}/frames`, `PUT frames/{fid}`, `POST lock` |
| `parameters.ts` | `GET /api/projects/{id}/parameters`, `POST recompute` |
| `export.ts` | `POST /api/projects/{id}/export/manim`, `GET /api/export/{job_id}` |
| `knowledge.ts` | `POST /api/knowledge/search`, `GET /api/knowledge/templates` |
| `versions.ts` | `POST /api/projects/{id}/versions`, `GET versions`, `POST restore` |
| `sse.ts` | SSE connection manager with auto-reconnect |

## Routes

| Path | Status |
|------|--------|
| `/` | Landing page |
| `/login` / `/register` | Auth pages |
| `/app` | Dashboard (project list + status filter + pagination) |
| `/app/new` | New project (natural language + file upload) |
| `/app/project/:projectId/plan` | Teaching plan confirmation |
| `/app/project/:projectId/edit` | Frame editor (edit + lock + regenerate + version save) |
| `/app/project/:projectId/play` | Interactive player (Dijkstra workbench + backend DSL fallback) |
| `/app/project/:projectId/export` | Export center (Manim config + render queue + download) |
| `/app/project/:projectId/versions` | Version history (list + restore + diff compare) |
| `/app/templates` | Knowledge template browser (search + subject/difficulty filter) |

See [the design specification](../docs/design/智能教学推演系统设计文档.md) for architecture and the [development tasks](../docs/开发任务与接口规范.md) for API contracts.

## Theme behavior

- Light theme is the default.
- The selected theme is persisted in local storage.
- Theme switching does not reset the current route or simulation frame.
- New colors should use semantic CSS variables from `src/styles/globals.css` rather than hard-coded values.

## Mock boundary

The local Dijkstra simulation frames in `workbench/simulation-model.ts` serve as both the default demo experience and a deterministic test fixture. When the backend is reachable, the player uses the server-provided DSL. When offline, it falls back to the local model automatically.
