# 前端架构与开发指南

## 1. 文档目标

本文档说明 EduFlow 当前前端的运行方式、目录职责、状态边界、测试方式和后续扩展约定。当前实现位于仓库的 `web/` 目录，采用纯前端本地模型演示 Dijkstra 推演，不连接后端。

## 2. 环境与启动

### 2.1 环境要求

- Node.js 20 或更高版本
- npm 10 或更高版本

### 2.2 首次安装

```bash
cd web
npm ci
```

`npm ci` 会严格按照 `package-lock.json` 安装依赖，适合新环境和 CI。仅在主动升级依赖时使用 `npm install`。

### 2.3 本地开发

```bash
npm run dev
```

默认访问 Vite 输出的本地地址。需要局域网访问时执行：

```bash
npm run dev -- --host 0.0.0.0
```

### 2.4 生产预览

```bash
npm run build
npm run preview
```

## 3. 目录职责

```text
web/src/
├─ app/                    应用入口、Provider 和路由
├─ components/
│  ├─ brand/               品牌标识
│  ├─ effects/             不承担业务功能的装饰动效
│  ├─ layout/              顶栏、侧边栏和页面外壳
│  ├─ ui/                  可复用基础组件
│  └─ workbench/           当前互动推演功能
├─ pages/                  页面级路由内容
├─ styles/                 全局样式和语义设计变量
├─ test/                   测试公共配置
└─ theme/                  主题状态、初始化脚本和 Provider
```

当前 `workbench/` 是单一功能模块。开始实现第二个完整业务模块时，应迁移为 `features/<功能名>/` 结构，将组件、模型、Hooks 和测试放在同一功能边界内，避免所有业务继续堆积到 `components/`。

## 4. 当前状态流

互动推演由 `WorkbenchPage` 维护三个页面状态：生成状态、计划步骤和当前帧。`simulation-model.ts` 提供 14 个确定性 Dijkstra 快照，图谱、讲解、距离表和时间轴读取同一个快照。

约束：

- 不在多个组件中复制距离、前驱或已确定节点集合。
- 新增算法时先定义领域模型，再让视图消费模型。
- 后端接入后，接口响应应先转换为前端领域模型，组件不直接依赖原始网络响应。
- 本地 Dijkstra 模型继续作为离线演示和自动化测试夹具。

## 5. 主题与样式

- 默认主题为浅色，支持浅色和深色切换。
- 主题选择由浏览器本地存储持久化。
- 颜色、边框和表面优先使用 `src/styles/globals.css` 中的语义变量。
- 基础控件使用 `components/ui/` 中的组件；不得在业务组件中重复实现按钮、标签页或下拉菜单。
- 动效必须尊重 `prefers-reduced-motion`，且不能阻塞首屏或承担必要信息表达。

## 6. 新增页面

1. 在 `src/pages/` 或新的 `src/features/<name>/pages/` 创建页面组件。
2. 在 `src/app/router.tsx` 注册路由。
3. 在 `AppShell.tsx` 的路由标题映射中补充标题。
4. 如需导航入口，在 `AppSidebar.tsx` 添加对应项。
5. 新增路由测试，覆盖页面标题、空状态、返回路径和 404 行为。
6. 同步更新 `web/README.md`、`web/README.zh-CN.md` 和本文档的路由状态。

## 7. 接入后端的推荐方式

建议新增：

```text
src/
├─ services/
│  ├─ api-client.ts         基础请求、超时和错误转换
│  └─ simulation-api.ts     推演相关接口
└─ features/simulation/
   ├─ contracts/            网络契约类型
   ├─ model/                前端领域模型
   └─ adapters/             契约到领域模型的转换
```

操作原则：

- 使用 `VITE_API_BASE_URL` 配置 API 地址，并在 `web/.env.example` 中提供无敏感信息的示例。
- 为加载、成功、空数据、失败、重试和取消分别提供可见状态。
- 不在组件内散落 `fetch` 调用。
- 对流式生成优先采用项目接口规范确定的 SSE 协议，并实现断线和取消处理。
- 后端不可用时允许显式进入本地演示模式，不静默伪装成真实生成结果。

## 8. 测试与质量门禁

```bash
npm run typecheck
npm run test
npm run lint
npm run build
```

完整验证：

```bash
npm run verify
```

提交前至少满足：

- TypeScript 类型检查通过。
- Vitest 全部通过。
- 生产构建通过。
- Lint 无错误；已有警告不得增加。
- 新交互具有键盘可达性和可读的辅助技术名称。
- 页面在浅色、深色、桌面和窄屏下完成一次人工检查。

## 9. 常见操作

### 增加依赖

```bash
cd web
npm install <package>
npm run verify
```

提交时同时包含 `package.json` 和 `package-lock.json`。

### 只运行相关测试

```bash
npm run test -- src/components/workbench/simulation-model.test.ts
```

### 清理并重新安装依赖

删除 `node_modules` 前先确认当前目录确实是 `web/`，然后重新执行 `npm ci`。不要删除 `package-lock.json` 来解决普通安装问题。

## 10. 文档约定

- 面向项目成员的主文档优先使用中文。
- 保留英文文档时，必须在同目录提供 `.zh-CN.md` 中文版并相互链接。
- 修改运行命令、目录结构、路由或技术边界时同步更新对应 README。
- 历史计划和已被当前实现取代的设计稿不作为有效规范继续保留；需要追溯时使用 Git 历史。
