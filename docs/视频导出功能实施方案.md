# EduFlow 视频导出功能实施方案

## 1. 文档目的

本文给出 EduFlow 从当前 Render 受限演示环境演进到可安全提供 Manim 视频导出的完整实施方案。方案覆盖功能边界、系统架构、基础设施、任务生命周期、安全隔离、持久化、测试、监控、发布、回滚和成本控制。

当前线上站点为：<https://eduflow-app-1hkd.onrender.com>。

本文不建议直接在现有免费 Web Service 进程中执行 Manim。视频渲染会运行生成的 Python 代码，并持续占用 CPU、内存和磁盘，必须与公开 API、用户凭据和数据库权限隔离。

## 2. 当前基础与限制

### 2.0 实施进度

截至 2026-09-22：

- [x] M1 视频 Worker 与无网络 Sandbox 镜像可构建；
- [x] Worker/Sandbox 单元测试通过（23 项）；
- [x] 无网络环境中的真实 Manim/FFmpeg MP4 smoke test 通过（8 项）；
- [x] 增加可重复执行的 `ops/video/verify-m1.ps1` 验收脚本；
- [ ] M2 外部 S3/R2 对象存储；
- [ ] M3 独立远程视频节点；
- [ ] M4 管理员线上灰度；
- [ ] M5 受限公开。

当前线上 `VIDEO_PUBLIC_ENABLED` 继续保持关闭。

### 2.1 已具备的能力

项目已经具备以下视频导出基础：

- `POST /api/projects/{id}/export/manim` 创建导出任务；
- `GET /api/export/{job_id}` 查询状态和进度；
- `DELETE /api/export/{job_id}` 取消任务；
- `GET /api/export/{job_id}/download/{filename}` 下载或预览产物；
- PostgreSQL 中的 `export_jobs` 和 `export_job_attempts` 持久任务记录；
- Worker 租约、心跳、超时恢复、有限重试和幂等处理；
- Manim 确定性脚本生成、可选 LLM 脚本生成和静态校验；
- 前端视频导出卡片、状态轮询、错误展示和下载入口；
- 用户级视频次数、并发数和存储额度配置；
- `render-worker` 与 `render-sandbox` 的生产部署骨架。

### 2.2 当前 Render 演示环境主动关闭的能力

当前 `render.yaml` 使用以下限制：

```text
MANIM_EXECUTION_MODE=disabled
VIDEO_PUBLIC_ENABLED=false
QUOTA_VIDEO_DAILY=0
QUOTA_VIDEO_MONTHLY=0
ARTIFACT_STORE_BACKEND=local
```

因此当前环境可以展示视频导出界面和数据结构，但不能实际执行公共视频渲染。

### 2.3 当前环境不能直接开启视频的原因

- 免费 Web Service 会休眠，长任务可能被中断；
- API 与渲染争抢 CPU 和内存会影响整个网站；
- 本地文件会随实例替换或重启丢失；
- Web Service 不应直接执行生成的 Python 代码；
- 当前没有每任务无网络沙箱的线上安全验收；
- 当前视频额度被设置为零；
- Render Web Service、Background Worker 之间不能依赖普通本地目录共享产物。

## 3. 目标与非目标

### 3.1 第一版目标

- 将已生成的教学帧导出为 MP4；
- 支持 480p 和 720p，默认 720p、30 FPS；
- 支持中文字幕文件，第一版不强制合成语音；
- 支持任务排队、进度查询、取消、重试和下载；
- 单用户同时最多一个视频任务；
- 产物保存到 S3 兼容对象存储；
- 渲染代码在无网络、无业务凭据的隔离环境运行；
- 管理员可暂停公共视频导出；
- 失败不会影响 Web API 和其他用户任务。

### 3.2 第一版非目标

- 4K 视频；
- 用户提交任意 Python 或 Manim 脚本；
- 实时协同剪辑；
- GPU 渲染；
- 无限期保存视频；
- 在免费 Render Web Service 内同步完成渲染；
- 默认开放 LLM 自由生成可执行 Manim 代码。

## 4. 推荐架构

```text
Browser
   |
   v
Render Web Service: Nginx + FastAPI
   |  创建任务、鉴权、额度、状态查询、签名下载
   +-------------------+
   |                   |
   v                   v
PostgreSQL          Redis
任务真相源           唤醒/进度通知
   |
   v
Render preparation worker
读取项目版本、生成脚本、执行静态校验
   |
   | 仅传递渲染包；不传递 API Key
   v
No-network render sandbox
Manim + FFmpeg + 字体；每任务资源限制
   |
   v
S3-compatible object storage
MP4 / SRT / 可审计的源文件与元数据
   |
   v
短时签名 URL 或受鉴权的 Range 下载
```

### 4.1 信任边界

| 组件 | 可以持有 | 禁止持有 |
|---|---|---|
| Web API | 数据库连接、Redis 连接、对象存储受限凭据、KMS 配置 | Manim 执行权限 |
| Preparation Worker | 数据库连接、必要时的用户模型凭据、对象存储写权限 | 公网对用户开放 |
| Render Sandbox | 单个任务输入、临时目录、受限 CPU/内存 | 网络、数据库、Redis、KMS、模型密钥、SMTP、云管理凭据 |
| 下载接口 | 用户身份、对象元数据、短时签名能力 | 对象存储管理权限 |

PostgreSQL 是任务状态的真相源。Redis 只用于快速通知或缓存，不能成为唯一任务记录。

## 5. 部署路线选择

### 5.1 推荐路线：独立 Linux 视频节点

保留现有 Render Web Service，在一台独立 Linux 主机部署：

- `render-worker`；
- `render-sandbox`；
- 两者共享一个仅用于任务交换的临时卷；
- 视频最终上传到 S3/R2，临时文件随后清理。

建议起步规格：

- 2–4 vCPU；
- 4–8 GB 内存；
- 20 GB 以上临时 SSD；
- Ubuntu LTS；
- Docker Engine 与 Compose；
- 每台机器并发渲染数为 1。

该路线最贴合仓库现有的 Worker/Sandbox 设计，也最容易实施无网络隔离。

### 5.2 备选路线：云容器任务

可使用按任务运行的容器服务，每个导出任务启动一个受限容器。该路线隔离更清晰、弹性更好，但需要新增任务调度适配层、镜像仓库、IAM 和日志聚合，首期实施复杂度更高。

### 5.3 不推荐路线：Render Web Service 内直接渲染

只适合开发机临时验证，不应对公共用户开放，原因包括资源争抢、超时、本地文件易失以及缺少真正的安全边界。

## 6. 分阶段实施计划

## 阶段 0：恢复生成链路前置条件

视频依赖项目已经成功生成教学帧，因此首先需要保证：

- 新站已经重新配置有效的生成模型凭据；
- 生成模型凭据已设为当前使用；
- 示例项目能够完成教学计划和帧生成；
- 项目版本中存在可导出的 `frames`；
- 不再出现 `Credential service is temporarily unavailable`。

验收：使用冒泡排序项目生成一组完整教学帧，并能正常预览。

## 阶段 1：本地视频闭环

### 任务

1. 构建固定依赖的渲染镜像：
   - Python 版本固定；
   - Manim 版本固定；
   - FFmpeg 版本可追溯；
   - 安装项目需要的 LaTeX 包；
   - 安装并显式选择中文字体。
2. 使用本地 PostgreSQL、Redis 和 MinIO 启动完整视频路径。
3. API 设置 `MANIM_EXECUTION_MODE=queue`。
4. Worker 设置 `MANIM_EXECUTION_MODE=worker`。
5. 第一版只启用 `MANIM_SCRIPT_MODE=deterministic`。
6. 验证 MP4、SRT 和 Manim 源文件生成。
7. 验证取消、超时、失败重试和 Worker 重启恢复。

### 验收

- 任务状态完整经过 `queued -> rendering -> completed`；
- 生成的 MP4 可播放且画面不是空白；
- 中文字体无方框或缺字；
- 视频内容与项目固定版本一致；
- 相同幂等键不会创建重复任务；
- Worker 被终止后任务能按租约机制恢复或进入明确失败状态；
- 下载接口支持 Range 请求。

## 阶段 2：对象存储持久化

### 任务

1. 选择 S3、Cloudflare R2 或其他 S3 兼容服务。
2. 创建独立 bucket，例如 `eduflow-artifacts`。
3. 使用以下键结构：

```text
exports/{user_id}/{project_id}/{job_id}/video.mp4
exports/{user_id}/{project_id}/{job_id}/subtitles.srt
exports/{user_id}/{project_id}/{job_id}/manifest.json
exports/{user_id}/{project_id}/{job_id}/source/main.py
```

4. Worker 只获得指定 bucket/prefix 的写入权限。
5. Web API 只获得读取、签名和必要删除权限。
6. 数据库保存对象键、大小、SHA-256、MIME 类型和创建时间。
7. 下载使用短时签名 URL，或由 API 鉴权后流式返回。
8. 配置生命周期：临时演示视频默认保留 7 天，可按套餐延长。
9. 上传成功并校验哈希后，才把任务标记为完成。

### 验收

- Web 和 Worker 重启后视频仍可下载；
- 用户不能猜测 URL 下载他人的视频；
- 过期对象能够自动清理；
- 数据库记录与对象存储内容能够进行一致性审计。

## 阶段 3：远程独立 Worker 与沙箱

### 任务

1. 部署 Preparation Worker；
2. 部署无网络 Render Sandbox；
3. 为每个任务创建独立工作目录；
4. 对容器设置：
   - 禁止网络；
   - 非 root 用户；
   - 只读根文件系统；
   - 临时可写目录；
   - CPU、内存、进程数和文件描述符限制；
   - 最大执行时间；
   - 最大工作区字节数和文件数；
   - 禁止挂载 Docker socket；
   - 不注入任何业务密钥。
5. Worker 负责准备脚本、执行静态校验、提交沙箱、上传产物和更新任务状态。
6. 沙箱输入仅包含渲染所需脚本、配置和静态素材。
7. 渲染结束后清理工作目录。

### 初始限制建议

```text
并发：每节点 1
超时：600 秒
单文件上限：500 MB
单任务工作区：1 GB
单任务文件数：5000
最大重试次数：3
默认画质：720p / 30 FPS
```

### 验收

- 沙箱无法访问公网；
- 沙箱中不存在数据库、Redis、KMS 或模型密钥；
- 恶意或异常脚本无法影响宿主机和其他任务；
- 超出资源限制的任务被终止并留下可诊断错误；
- Worker 停机不影响网站浏览与普通生成功能。

## 阶段 4：管理员灰度

### 配置原则

API：

```text
MANIM_EXECUTION_MODE=queue
MANIM_SCRIPT_MODE=deterministic
VIDEO_PUBLIC_ENABLED=false
VIDEO_PUBLIC_ISOLATION_APPROVED=false
QUOTA_VIDEO_DAILY=1
QUOTA_VIDEO_MONTHLY=5
QUOTA_VIDEO_CONCURRENT=1
```

Worker：

```text
MANIM_EXECUTION_MODE=worker
MANIM_SCRIPT_MODE=deterministic
```

保持公共开关关闭，仅管理员执行真实导出。管理员测试至少覆盖：

- 排序算法；
- 图算法；
- 代码展示；
- 数学公式；
- 中文长文本；
- 取消任务；
- Worker 重启；
- 对象存储暂时不可用；
- 超时与重试；
- 同一项目连续导出。

### 灰度通过门槛

- 连续 50 个代表性任务成功率不低于 95%；
- 无跨用户访问；
- 无密钥进入沙箱；
- 无不可恢复的永久排队任务；
- 失败任务均有用户可理解的错误；
- 720p 渲染耗时与资源消耗达到预设预算。

## 阶段 5：受限公开

完成安全评审后才能设置：

```text
VIDEO_PUBLIC_ENABLED=true
VIDEO_PUBLIC_ISOLATION_APPROVED=true
```

同时保持：

- 每日 1 次；
- 每月 5 次；
- 每用户并发 1；
- 默认 720p；
- 4K 禁用；
- LLM Manim 脚本模式禁用；
- 仅允许系统支持的模块和渲染参数。

先开放白名单用户，再逐步扩大范围。公共开关必须能够在不重新构建镜像的情况下快速关闭。

## 阶段 6：生产化与扩容

- 按最老任务等待时间扩缩 Worker；
- 不在单台节点上盲目增加高并发；
- 区分排队、准备、渲染、上传各阶段耗时；
- 增加死信任务和管理员重试入口；
- 增加对象存储一致性巡检；
- 增加容量预测和成本告警；
- 评估 TTS，并将其作为独立可选流水线；
- 只有在确定性模式稳定后才评估 LLM Manim 模式；
- 如启用 LLM 模式，模型凭据只能在 Preparation Worker 中短暂解密，绝不能进入 Render Sandbox。

```text
DATABASE_URL=...

MANIM_SCRIPT_MODE=deterministic
ARTIFACT_STORE_BACKEND=minio

```

变量名应以 `agent/config.py` 的实际定义为准；生产环境通过 Secret Manager 或平台 Secret 注入，不写入 Git。

### 7.2 Worker 必要配置

```text
DATABASE_URL=...
REDIS_URL=...
MANIM_EXECUTION_MODE=worker
MANIM_SCRIPT_MODE=deterministic
ARTIFACT_STORE_BACKEND=minio
MINIO_ENDPOINT=...

```

### 7.3 Sandbox 配置

Sandbox 不应拥有上述 Secret。它仅接收一次性任务目录和非敏感渲染参数。

## 8. 状态机与用户体验

推荐对外状态：

```text
queued -> preparing -> rendering -> uploading -> completed
   |          |            |            |
   +----------+------------+------------+-> failed
   +--------------------------------------> cancelled
```

如果数据库现有状态暂时只有 `queued`、`rendering`、`completed`、`failed` 和 `cancelled`，可以先把 `preparing` 与 `uploading` 表示为进度详情，之后再迁移为正式状态。

前端应展示：

- 当前阶段；
- 排队位置或估算等待时间；
- 进度百分比；
- 已用时间；
- 取消按钮；
- 可重试或不可重试的失败提示；
- 视频预览；
- MP4 与字幕下载；
- 文件大小和过期时间。

## 9. 安全要求

### 9.1 输入控制

- 第一版只接受结构化 DSL，不接受用户 Python；
- 强制重新编译和验证持久化帧；
- 限制帧数、文本长度、素材数量和参数范围；
- 禁止任意文件路径和远程 URL；
- 对上传素材进行类型、大小和内容检查。

### 9.2 执行隔离

- 每任务独立容器或等价隔离；
- 默认无网络；
- 非 root；
- 不共享宿主敏感目录；
- 不挂载 Docker socket；
- 禁止特权模式；
- 资源和时间硬限制；
- 任务结束强制清理。

### 9.3 数据和权限

- 所有导出 API 校验项目所有权；
- 管理员绕过必须记录审计；
- 下载 URL 短时有效；
- 对象存储 bucket 不公开；
- 日志不得包含模型 API Key、Cookie、签名 URL 查询参数或完整用户材料；
- Worker 和 API 使用不同服务身份。

## 10. 测试计划

### 10.1 单元测试

- DSL 到 Manim 的转换；
- 脚本静态校验；
- 配置边界；
- 配额、并发和幂等；
- 对象键生成和所有权检查；
- 错误到用户提示的映射；
- 重试退避与最大尝试次数。

### 10.2 集成测试

- API 创建任务后 Worker 可以领取；
- Worker 生成产物并更新数据库；
- Redis 中断时任务不会丢失；
- Worker 崩溃后租约过期恢复；
- 对象存储失败后任务按策略重试；
- 取消操作能阻止后续发布产物；
- Range 下载和签名 URL 正常。

### 10.3 安全测试

- 沙箱访问公网失败；
- 沙箱读取宿主路径失败；
- fork bomb、超大文件和无限循环被限制；
- 恶意文件名不能目录穿越；
- 用户 A 不能查询或下载用户 B 的任务；
- 日志和产物中不存在 Secret。

### 10.4 视觉回归

建立一组黄金项目，对生成视频抽帧比较：

- 冒泡排序；
- 二分查找；
- BFS/DFS；
- Dijkstra；
- 代码逐行演示；
- 数学公式；
- 中文长文本和字幕。

人工检查空白帧、遮挡、越界、字体、字幕、颜色对比和节奏。

## 11. 监控与告警

至少记录：

- 队列长度；
- 最老任务等待时间；
- 各状态任务数量；
- 成功率和失败分类；
- P50/P95 排队、渲染和上传耗时；
- Worker 心跳与租约过期次数；
- 每任务 CPU、内存、临时磁盘峰值；
- 输出文件大小；
- 对象存储容量和请求错误；
- 用户配额拒绝次数。

建议告警：

- 最老排队任务超过 10 分钟；
- 连续 5 个任务失败；
- Worker 无心跳；
- 任务租约过期；
- 对象存储上传连续失败；
- 临时磁盘超过 80%；
- 一小时成功率低于 90%。

## 12. 发布与回滚

### 12.1 发布顺序

1. 数据库迁移；
2. 对象存储和 IAM；
3. Worker 镜像；
4. Sandbox 镜像；
5. 管理员模式部署；
6. 冒烟测试；
7. 白名单灰度；
8. 受限公开。

### 12.2 回滚开关

发生异常时立即设置：

```text
VIDEO_PUBLIC_ENABLED=false
```

这会阻止普通用户创建新任务。随后：

1. 保留数据库任务记录和已上传产物；
2. 暂停 Worker 领取新任务；
3. 允许正在上传的可信任务完成，或显式取消；
4. 回滚 Worker/Sandbox 镜像；
5. 验证后恢复管理员导出；
6. 最后重新开放公共导出。

不要通过删除任务表或 bucket 作为回滚手段。

## 13. 容量与成本控制

初期使用以下保守策略：

- 默认 720p；
- 单用户并发 1；
- 单节点并发 1；
- 每日 1 次、每月 5 次；
- 任务超时 10 分钟；
- 产物保留 7 天；
- 管理员可关闭导出；
- 超出额度不自动升级资源。

稳定后根据真实数据计算：

```text
单视频成本 = Worker 计算成本 + 对象存储成本 + 下载流量成本 + 可选模型/TTS 成本
```

扩容优先依据最老任务等待时间，而不是仅依据 CPU。

## 14. 里程碑与交付物

| 里程碑 | 主要交付物 | 完成标准 |
|---|---|---|
| M0 前置恢复 | 有效模型连接、示例项目 | 可生成完整教学帧 |
| M1 本地闭环 | 固定渲染镜像、本地 Worker/Sandbox | 可生成并下载 720p MP4 |
| M2 持久存储 | S3/R2 适配、签名下载、生命周期 | 重启后视频仍可用 |
| M3 远程隔离 | 独立视频节点、无网络沙箱 | 安全与故障测试通过 |
| M4 管理员灰度 | 监控、告警、配额、运维手册 | 50 个样本成功率不低于 95% |
| M5 受限公开 | 白名单与公共开关 | 普通用户按额度稳定导出 |
| M6 生产化 | 扩缩容、成本与一致性巡检 | 满足正式服务 SLO |

## 15. 建议的实施顺序

1. 不改当前线上视频开关；
2. 先修复模型接入并准备黄金示例项目；
3. 完成 M1 本地闭环；
4. 接入对象存储；
5. 部署独立 Worker/Sandbox；
6. 管理员灰度并收集至少 50 次真实渲染数据；
7. 完成安全评审；
8. 才设置 `VIDEO_PUBLIC_ENABLED=true` 和 `VIDEO_PUBLIC_ISOLATION_APPROVED=true`；
9. 逐步扩大用户范围和额度。

当前最合理的下一项开发任务是 **M1：本地视频导出闭环**，而不是直接修改线上 Render Web Service。
