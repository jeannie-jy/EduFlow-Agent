# EduFlow-Agent 部署说明指南

## 1. 当前部署信息

EduFlow-Agent 受限演示版已经部署到 Render：

- 网站地址：<https://eduflow-limited.onrender.com>
- 部署平台：Render
- 部署区域：Singapore
- 部署分支：`feature/production-deployment`
- Blueprint：仓库根目录的 `render.yaml`
- Web 服务：`eduflow-limited`
- PostgreSQL：`eduflow-limited-db`
- Key Value：`eduflow-limited-kv`
- 当前套餐：Free

这是用于功能体验和部署验证的受限演示环境，不是正式生产环境。不要在其中保存重要、敏感或
唯一副本的数据。

## 2. 网站能实现什么

### 2.1 用户与账号

- 注册和登录 EduFlow 账号；
- 使用安全 Cookie 保持登录会话；
- 查看和修改个人账号设置；
- 在“模型接入”中保存用户自己的模型供应商凭据；
- 为生成和 Embedding 分别选择模型连接；
- 查看个人用量和配额状态。

本部署采用 BYOK（Bring Your Own Key）模式。平台不提供公共模型 Key，用户必须在账号设置中
配置自己的 DeepSeek、DashScope 或受支持的 OpenAI 兼容模型凭据，才能执行真实生成。

### 2.2 教学项目管理

- 创建教学推演项目；
- 设置主题、课程、受众和难度等教学信息；
- 查看项目列表和项目详情；
- 保存项目工作副本；
- 管理项目版本并查看历史快照；
- 删除当前用户拥有的项目。

项目、版本、生成状态和大部分结构化结果保存在 Render PostgreSQL 中。

### 2.3 AI 教学内容生成

- 根据教学主题生成教学方案；
- 在生成过程中查看可恢复的 SSE 进度；
- 审核 Agent 生成的教学计划；
- 批准或拒绝计划后继续工作流；
- 生成教学帧、知识卡片、学习路径、误区分析、对比内容和测验；
- 对部分模块执行重新生成；
- 调整参数并预览对下游内容的影响；
- 保存不可变项目版本。

生成链路基于 LangGraph，主要过程包括 Planner、Knowledge、Coder、Quality 和 Reflection。模型
供应商产生的 token 费用由用户自己的 API 账号承担。

### 2.4 教学成果展示

- 查看教学帧与分步内容；
- 查看知识卡片、知识图谱和思维导图；
- 使用参数实验和算法演示；
- 查看学习路径和模块结果；
- 完成选择题、填空题等测验；
- 运行浏览器内隔离的交互演示；
- 使用模板创建或体验示例项目。

### 2.5 权限与安全基础

- 用户只能访问自己拥有的项目与数据；
- 支持学生、教师和管理员角色；
- 模型凭据经过加密后保存；
- API 文档和内部 Prometheus 指标不对公网开放；
- 前端与 API 使用同源地址，避免跨域 Cookie 问题；
- 生成任务有每日、每月和并发配额；
- 数据库支持 pgvector，可用于知识检索和 Embedding。

## 3. 当前受限功能

### 3.1 暂不可用或不可靠

- **材料解析任务**：没有部署独立 `task-worker` 和无网络材料沙箱，解析任务可能一直保持排队；
- **反馈自动修订**：普通反馈可以保存，但需要后台任务的反思修订不会自动消费；
- **视频导出**：Manim Worker 和渲染沙箱未部署，视频功能关闭；
- **持久化文件存储**：当前使用容器本地临时目录，上传文件会在重启或重新部署后丢失；
- **邮件验证与找回邮件**：没有配置 SMTP，邮箱验证功能关闭；
- **生产级密钥管理**：当前使用 Render 自动生成的本地 KEK，不是生产 KMS Bridge；
- **高可用与灾难恢复**：免费实例没有正式生产所需的 HA、PITR 和恢复承诺；
- **完整监控**：没有部署 OpenTelemetry Collector、Prometheus 和外部告警。

### 3.2 Render 免费套餐限制

- Web 服务闲置后可能休眠，首次访问需要等待冷启动；
- 免费 PostgreSQL 容量有限，并会在创建约 30 天后到期；
- 免费 Key Value 不提供持久化保证；
- 免费 Web 服务资源有限，复杂或并发生成可能超时或内存不足；
- 不应把此环境当作长期数据存储或正式对外服务。

## 4. 首次使用

### 4.1 注册账号

1. 打开 <https://eduflow-limited.onrender.com>；
2. 如果页面处于冷启动状态，等待一段时间后刷新；
3. 点击注册；
4. 创建测试账号并登录。

当前演示环境允许注册且不要求邮箱验证。公开分享网站时应注意免费数据库容量和恶意注册风险。

### 4.2 配置模型连接

1. 登录后进入“账号设置”或“模型接入”；
2. 新增生成模型连接；
3. 选择供应商并填写 API Key、模型和用途；
4. 按需要再新增 Embedding 连接；
5. 将可用连接设置为当前活动连接；
6. 使用小型请求验证连接。

请使用专门为测试创建、带有额度限制的 API Key，不要使用拥有过高权限或无限预算的主账号 Key。

### 4.3 创建第一个项目

1. 进入工作台；
2. 点击“新建推演”；
3. 填写教学主题、目标受众和难度；
4. 暂时不要上传材料；
5. 选择少量生成模块；
6. 启动生成并观察进度；
7. 审核生成计划后继续；
8. 检查教学帧、知识卡片和测验结果。

建议首次生成使用简单主题和较少模块，以降低免费实例资源压力和模型调用成本。

## 5. Render 部署结构

```text
Browser
   |
   v
Render HTTPS Load Balancer
   |
   v
eduflow-limited Web Service
   |-- Nginx: 静态前端、同源 /api 代理、SSE
   `-- FastAPI: 认证、项目、LangGraph、业务 API
            |-- Render PostgreSQL 16 + pgvector
            `-- Render Key Value
```

Nginx 与 FastAPI 运行在同一个 Render Web 容器内。容器启动时会：

1. 根据 Render 的 `PORT` 生成 Nginx 配置；
2. 创建运行时临时目录；
3. 执行 `alembic upgrade head`；
4. 启动 FastAPI；
5. 启动 Nginx 并对外提供同源网站。

## 6. 自动部署与手动部署

### 6.1 自动部署

Render Blueprint 配置了 `autoDeployTrigger: commit`。向
`feature/production-deployment` 推送新 commit 后，Render 通常会自动开始部署。

在 Render 控制台的 Web Service → Deploys 中可以查看：

- 触发部署的 commit；
- 构建日志；
- 数据库迁移输出；
- 容器启动日志；
- 健康检查和最终状态。

### 6.2 手动部署

如果自动部署没有触发：

1. 打开 `eduflow-limited` Web Service；
2. 进入 Deploys；
3. 点击 **Manual Deploy**；
4. 选择 **Deploy latest commit**；
5. 等待状态变为 **Live**。

### 6.3 健康检查

浏览器或命令行访问：

```text
https://eduflow-limited.onrender.com/api/health
```

正常情况下返回包含 `status: ok` 的 JSON。Render 使用该端点判断 Web Service 是否健康。

## 7. 常见故障排查

### 网站长时间打不开

- 免费 Web Service 可能正在冷启动；
- 在 Render Deploys/Logs 中检查是否出现新的启动记录；
- 等待一段时间后刷新；
- 检查 `/api/health`。

### 部署显示 Failed

查看日志最下方第一条红色错误，而不是只看前面的警告。常见阶段包括：

- Docker 镜像构建；
- 前端 TypeScript/Vite 构建；
- Alembic 数据库迁移；
- Nginx 或 FastAPI 启动；
- Render 端口检测和健康检查。

### 可以打开页面但生成失败

- 检查是否已经保存并启用生成模型凭据；
- 检查供应商余额、模型名称和 API Key 权限；
- 检查是否达到每日、每月或并发配额；
- 查看浏览器错误提示和 Render 应用日志；
- 首次测试不要选择材料解析或视频模块。

### 材料一直显示处理中

这是当前受限版的已知限制。材料解析需要独立 Worker 和隔离沙箱，本部署没有启用。不要反复
提交解析任务，也不要上传需要长期保存的文件。

### 重新部署后文件消失

这是 Render 临时文件系统的预期行为。项目结构化数据保存在 PostgreSQL，但容器本地上传物和
导出物不会持久保存。正式版本必须接入 S3 兼容对象存储。

## 8. 数据与安全提示

- 不上传个人隐私、商业机密、考试原卷或唯一副本；
- 不把模型 API Key 写入 Git、聊天截图或 Render 日志；
- 使用受限、可轮换、设有预算的测试 Key；
- 免费 PostgreSQL 到期前导出需要保留的数据；
- 不依赖免费 Key Value 保存关键状态；
- 不在没有备份和恢复演练的情况下升级为正式服务；
- 停止演示时应关闭注册，必要时删除测试账号和吊销模型 Key。

## 9. 升级为完整版本需要完成什么

正式部署前至少需要：

1. 接入持久化 S3 兼容对象存储；
2. 将材料解析和渲染的共享卷交接改造成对象存储或可靠任务队列；
3. 部署独立 task-worker、maintenance 和受限沙箱；
4. 部署生产 KMS Bridge，轮换本地演示 KEK；
5. 配置 SMTP、邮箱验证和管理员 MFA；
6. 使用付费 PostgreSQL/Key Value，并配置备份、PITR 和恢复演练；
7. 接入集中日志、指标、追踪和告警；
8. 完成容量、故障注入、权限隔离和安全测试；
9. 使用自定义域名，并重新校验 Origin、Cookie 和可信代理配置；
10. 关闭演示 Blueprint，按 `ops/production/README.md` 迁移到正式拓扑。
