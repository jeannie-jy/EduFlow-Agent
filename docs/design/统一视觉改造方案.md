# EduFlow 前端统一视觉改造方案

> 版本：v1.0  
> 范围：公开宣传页、登录/注册、应用框架、项目列表、模板库、新建推演、公开交互案例、教学成果组件  
> 核心目标：在不改变业务能力的前提下，把当前分散的界面统一成一套清晰、可信、可操作的「互动教学手稿」。

---

## 1. 设计结论

EduFlow 不应被设计成通用 AI SaaS，也不应继续保留登录页的蓝紫渐变风格。全站统一采用已经在宣传页验证过的视觉方向：

**学术纸本 × 互动技术手稿 × 理性教学实验台**

三种体验角色分别承担不同职责：

- **纸本感**建立教育品牌的温度与可信度。
- **技术手稿感**表达每一步知识变化都有依据、可回看、可校对。
- **实验台感**保证表单、参数、状态表、播放器和编辑器高效易用。

视觉不是复古装饰。公开页可以更有编辑感；进入工作台后应逐渐克制，优先保证扫描效率与操作密度。

## 2. 产品层级

### 2.1 两条用户路径

#### 学生路径

`首页 → 公开案例 → 单步推演 → 调整参数 → 理解结果 → 基于案例继续学习`

重点：画布、当前步骤、前后变化、播放控制和少量关键参数。

#### 教师路径

`首页/工作台 → 描述教学目标 → 确认教学计划 → 选择产出 → 生成与校验 → 编辑/导出`

重点：教学目标、计划审核、模块选择、质量反馈、版本和导出。

### 2.2 页面视觉层级

| 层级 | 页面 | 视觉策略 |
|---|---|---|
| 品牌叙事层 | 首页、公开案例 | 较强的衬线标题、章节编号、宽幅图版 |
| 转化层 | 登录、注册 | 保留品牌气质，但压低装饰，突出表单 |
| 工作层 | 项目列表、模板库、新建/编辑 | 无衬线为主、语义色、紧凑布局、稳定操作区 |
| 沉浸层 | 推演播放器、教学成果 | 画布优先，状态与控制围绕当前任务组织 |

## 3. 统一视觉语言

### 3.1 色彩

沿用现有语义色，不再在业务组件中使用 `slate-*`、`indigo-*`、`blue-*`、`green-*`、`red-*` 等固定色类。

| 语义 | Light | Dark | 使用场景 |
|---|---:|---:|---|
| 页面背景 | `#F3EBD8` | `#1B1814` | 页面底色 |
| 主表面 | `#FFF8E8` | `#24201B` | 卡片、表单、弹层 |
| 次表面 | `#ECE1C8` | `#2E2922` | 选中项、辅助面板 |
| 主文字 | `#25231F` | `#EFE4CE` | 标题、正文 |
| 次文字 | `#686052` | `#BEB29E` | 说明、元数据 |
| 品牌暗红 | `#8B3A32` | `#D58A78` | 主要行动、品牌强调 |
| 交互墨绿 | `#315E59` | `#70A59A` | 链接、选中、当前对象 |
| 黄铜 | `#B67A2B` | `#D6AA5F` | 进度、顺序、提醒 |
| 成功 | `#54755B` | `#7AA184` | 完成、校验通过 |
| 错误 | `#A8463A` | `#E18478` | 失败、风险、删除 |

规则：

1. 品牌暗红只用于主行动和品牌识别，避免整页泛红。
2. 墨绿负责“当前、可交互、已选择”，与暗红主行动区分。
3. 状态不能只靠颜色，必须同时带文字、图标或形状。
4. 错误面板使用低饱和背景和明确下一步，不展示 HTTP 状态码。
5. Dark 模式与 Light 模式使用同一语义层级，不复制两套布局。

### 3.2 字体

| 内容 | 字体 | 建议 |
|---|---|---|
| 首页 Hero、章节标题 | Georgia / Noto Serif SC / Songti SC | 仅用于叙事和品牌标题 |
| 页面标题、正文、表单、按钮 | Inter / Noto Sans SC / 系统无衬线 | 工作台默认字体 |
| 参数、帧号、边权、时间、代码 | JetBrains Mono / 系统等宽 | 只用于真实数据 |

工作台字号建议：

- 页面标题：28/36，字重 700。
- 区块标题：18/28，字重 650。
- 正文：15/24。
- 辅助文字：13/20，不低于 12px。
- 按钮：14/20，字重 600。

### 3.3 表面、边框和圆角

- 普通结构使用 1px 语义边框。
- 工作台卡片圆角统一为 10px；输入和按钮统一为 8px。
- 重要案例可使用双层纸张错位，普通表单与列表禁止使用。
- 阴影只用于浮层、拖拽对象和悬停反馈，页面主体靠边框分层。
- 避免“卡片套卡片”；同一层级优先用分隔线和小标题组织。

### 3.4 间距与密度

采用 4px 基础网格：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。

- 页面左右留白：桌面 32px，平板 24px，移动端 16px。
- 内容区最大宽度：普通工作页 1120px；长表单 760px；沉浸画布可占满。
- 表单字段间距 20–24px。
- 卡片内部间距 16–24px。
- 移动端触控目标不小于 44×44px。

## 4. 应用框架重构

### 4.1 桌面端

保留左侧导航，但简化顶部信息：

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 品牌         │ 当前页面/项目                主题  更多      │
│ 新建推演     ├─────────────────────────────────────────────┤
│              │                                             │
│ 我的推演     │                 页面内容                    │
│ 模板库       │                                             │
│              │                                             │
│ 当前课程     │                                             │
└──────────────┴─────────────────────────────────────────────┘
```

规则：

- 顶栏只显示一个清晰标题；不要同时出现面包屑、返回链接和重复页面标题。
- 在项目内部使用 `项目名 / 当前阶段`；在一级页面只显示页面名。
- “更多”按钮只有存在真实操作时才显示，避免空入口。
- 侧栏收起后，所有图标必须提供可访问名称和 Tooltip。

### 4.2 移动端

- 侧栏变为抽屉。
- 顶栏保留：菜单、当前页面、主题/更多。
- 核心表单和编辑流程使用底部固定主操作栏。
- 页面内容只允许一个主要纵向滚动容器，避免内外双滚动。

## 5. 页面改造方案

### 5.1 宣传首页

保留现有视觉方向，但简化首屏演示。

首屏结构：

1. 价值主标题。
2. 一段说明。
3. 主行动“体验交互推演”。
4. 次行动“创建新的推演”。
5. 精简版演示：算法图 + 当前步骤 + 播放入口。

距离表、参数面板和完整时间轴放到后续“交互案例”章节或点击展开后的沉浸状态。这样可以让用户先理解价值，再进入复杂操作。

### 5.2 登录与注册

删除蓝紫渐变，改为以下结构：

```text
桌面：左 42% 品牌手稿区 / 右 58% 表单区
移动：品牌标识 + 表单，不保留大面积装饰空白
```

品牌区可以使用暖色次表面、暗红章节编号和一个简化算法状态图，不使用渐变与发光效果。

表单要求：

- 使用真实 `<label>`。
- 错误信息与字段关联，并设置 `aria-invalid`。
- 提交错误在表单顶部汇总，同时保留字段级提示。
- 密码显示按钮至少 44×44px。
- 注册条款与隐私政策是可点击链接。
- 移动端表单从视觉中心适度上移，减少顶部空白。

### 5.3 项目列表

页面结构：

```text
我的推演                         [新建推演]
最近编辑与已创建的教学推演
[搜索项目]  [状态筛选]  [排序]

项目卡片/列表
```

建议默认使用列表式卡片，展示：标题、主题、状态、最后编辑时间、产出数量。删除等低频操作进入卡片菜单。

状态设计：

- 加载：骨架屏。
- 空数据：解释价值 + 新建行动 + 示例入口。
- 筛选无结果：保留筛选条件 + 清除筛选。
- 网络失败：温和错误条 + 重试 + 新建本地草稿入口。
- 删除：使用正式确认弹层，不使用 `window.confirm`。

### 5.4 模板库

结构调整为：

```text
知识模板库
从经过整理的知识点开始创建
[搜索................................] [筛选]
[全部] [算法] [数据结构] [操作系统] ...

模板卡片网格
```

模板卡片至少包含：

- 知识点名称。
- 学科和难度。
- 预计帧数/时长。
- 可生成产出。
- “预览”和“使用此模板”两个层级明确的操作。

错误、无模板、搜索无结果三种状态必须互斥。

### 5.5 新建推演

将当前流程从“先选 10 个模块”调整为更符合教师思维的三步：

#### 第一步：定义教学目标

- 推演标题。
- 想讲解的知识点。
- 学习对象与难度（使用合理默认值，可展开修改）。
- 可选：从模板开始。

主行动：`生成教学计划`。

#### 第二步：审核教学计划

计划不再展示 JSON，而是分区展示：

- 学习目标。
- 先修知识。
- 教学步骤。
- 关键例子。
- 常见误区。
- 预计时长。

每一区支持编辑或请求修改。主行动：`确认计划并选择成果`。

#### 第三步：选择成果并生成

默认推荐 3–4 项核心成果，例如：

- 推演脚本（必选）。
- 知识卡片。
- 小练习。
- 思维导图。

其他高级成果折叠到“更多产出”。每项显示用途、预计生成时间和推荐原因。

主行动区持续显示：`已选择 4 项 · 预计约 2 分钟   开始生成`。

规则：

- 不能出现实际模块 5 个、计数却为 10 的状态。
- 后端不可用时，不显示伪造的可用模块数量。
- 移动端步骤条显示“目标 / 计划 / 成果”，不能只显示数字。
- 桌面和移动端都让主行动在合理滚动范围内可见；移动端使用固定底栏。

### 5.6 Dijkstra 公开演示

桌面布局：

```text
┌────────────────────────────────────┬────────────────────┐
│ 算法画布                            │ 当前步骤            │
│                                    │ 状态表 / 参数 Tab   │
│                                    │                    │
├────────────────────────────────────┴────────────────────┤
│ 上一帧  播放/暂停  下一帧   02/14   ━━━━━●━━━━          │
└─────────────────────────────────────────────────────────┘
```

- 播放控制固定在演示容器底部，始终可见。
- 右侧只展示“当前步骤”和“状态表/参数”之一，降低信息竞争。
- 时间轴使用可拖动进度条或至少 44px 的帧按钮。
- 参数变化显示“预览变化 → 正在重算 → 已更新”的反馈。
- 图缩放控件使用项目图标与统一尺寸，不保留外部组件默认外观。

移动端顺序：当前步骤 → 画布 → 播放控制 → 状态/参数折叠面板。核心体验不依赖精确拖拽。

## 6. 核心组件规范

### 6.1 按钮

- Primary：品牌暗红，页面只能有一个主要行动焦点。
- Secondary：透明/主表面 + 语义边框。
- Ghost：低频工具操作。
- Destructive：只在删除确认等高风险场景使用。
- Icon Button：最小 36×36px，移动端与播放器为 44×44px。

所有按钮具备默认、悬停、按下、焦点、禁用、加载状态。加载时保持宽度稳定。

### 6.2 表单

- 标签位于输入上方，不使用 placeholder 代替标签。
- 帮助文字在输入前或输入后保持一致。
- 错误使用图标 + 文字 + 语义色。
- 必填项使用文字说明或星号，并在表单开头解释星号含义。
- 长表单使用区块标题和分隔线，减少大卡片层层包裹。

### 6.3 状态反馈

统一五类状态：

| 状态 | 表达 |
|---|---|
| 信息 | 中性图标 + 简短说明 |
| 进行中 | 进度 + 当前正在做什么 + 可取消性 |
| 成功 | 完成内容 + 下一步行动 |
| 警告 | 影响说明 + 继续/返回 |
| 错误 | 用户语言 + 保留内容说明 + 重试/替代路径 |

禁止直接展示 `HTTP 502`、堆栈、Agent 节点名或内部阶段名。

### 6.4 卡片

卡片必须至少满足一个目的：导航、选择、比较或承载独立结果。纯粹为了包裹内容的卡片改用区块和分隔线。

### 6.5 弹层

替换原生 `confirm` 与 `prompt`：

- 删除确认弹层说明对象、后果和恢复可能性。
- 修改计划弹层保留当前计划上下文，并提供多行反馈输入。
- 焦点进入弹层后受控，关闭后返回触发按钮。

## 7. 响应式和无障碍验收

### 响应式

- 390px、768px、1024px、1440px 四个基准宽度没有横向页面滚动。
- 移动端主操作不被裁切或埋在过长内容之后。
- 筛选器可折叠或横向滚动，并提供可见的滚动暗示。
- 200% 浏览器缩放时仍能完成登录、新建推演和案例播放。

### 无障碍

- 所有字段有程序化标签。
- 所有图标按钮有可访问名称。
- 键盘可以完成导航、登录、筛选、模块选择和播放器操作。
- 焦点环在 Light/Dark 下清晰可见。
- 错误与动态状态通过 `aria-live` 等方式播报。
- 动画遵守 `prefers-reduced-motion`。
- 文本和关键控件对比度按 WCAG AA 验证。

## 8. 分阶段实施

### Phase 1：设计系统收口（最高优先级）

目标：先解决“像三个产品”和 Dark 模式不可读。

- 清理业务组件中的固定 slate/indigo/blue/green/red/white 色值。
- 建立统一语义状态色和表面组件。
- 统一按钮、输入、卡片、错误、空状态、对话框。
- 逐页验证 Light/Dark。

主要范围：

- `web/src/styles/globals.css`
- `web/src/features/auth/*`
- `web/src/pages/Dashboard.tsx`
- `web/src/pages/TemplateBrowser.tsx`
- `web/src/features/modules/*`
- `web/src/components/workbench/*`

### Phase 2：创建流程重构

- 改为“教学目标 → 计划审核 → 选择成果”。
- 修复模块计数与加载回退状态。
- 教学计划与质量报告改为结构化 UI。
- 增加固定主操作栏和正式反馈弹层。

主要范围：

- `web/src/pages/ProjectWorkspace.tsx`
- `web/src/features/modules/ModuleSelector.tsx`
- `web/src/features/modules/ModuleCard.tsx`
- 新增计划编辑与生成操作组件。

### Phase 3：公开演示重构

- 画布、当前步骤和播放条重新布局。
- 参数与状态表改为切换面板。
- 增大时间轴和图控制触点。
- 补充参数重算状态反馈。

主要范围：

- `web/src/features/demo/DijkstraDemo.tsx`
- `web/src/features/demo/DemoTimeline.tsx`
- `web/src/features/demo/DemoParameterPanel.tsx`
- `web/src/features/demo/DemoStatusTable.tsx`

### Phase 4：页面框架和品牌统一

- 重做认证页品牌区。
- 精简 AppShell 顶栏和重复导航。
- 优化项目列表和模板卡片。
- 最后进行动效与细节打磨。

## 9. 最终验收标准

改造完成后，应满足：

1. 从首页进入登录页和工作台时，明显属于同一品牌。
2. 任意业务页切换 Dark 后不存在不可读标题、白色空状态或固定浅色卡片。
3. 用户能用一句话说明新建流程当前处于哪一步、下一步会发生什么。
4. 模块数量、生成状态和提示文案始终与真实数据一致。
5. 后端不可用时，界面使用用户语言，并提供可执行的替代行动。
6. Dijkstra 演示的播放控制在桌面和移动端都容易找到和操作。
7. 登录、新建推演和演示播放可仅使用键盘完成。
8. 390px 移动端和 200% 缩放下没有关键操作被裁切。
9. 所有主要页面通过 Light/Dark、空、加载、错误和成功状态截图验收。
10. 新增视觉改造不破坏现有自动化测试，并补充关键交互与主题回归测试。

---

## 10. 推荐先实施的最小闭环

第一轮开发建议只完成以下四件事：

1. 语义颜色收口和 Dark 模式修复。
2. 登录/注册品牌统一与表单可访问性。
3. Dashboard、模板库的错误/空状态互斥与用户化文案。
4. 新建页模块计数、步骤文案和移动端主操作修复。

这四项完成后，全站会先从“视觉割裂且有状态矛盾”提升到“品牌统一、基础可靠”，再进入播放器和流程结构级重构。
