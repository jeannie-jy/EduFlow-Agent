# EduFlow 核心功能模块全面改造方案

> 版本：v1.0  
> 适用范围：推演脚本、算法展示、教学视频、思维导图、知识卡片、练习、算法对比、常见误区、学习路径、代码沙箱、交互 Demo 及其统一成果工作台。  
> 目标：把当前“生成后顺序堆叠的十张结果卡片”，升级为可理解、可试验、可编辑、可校验、可发布的一体化教学内容工作台。

---

## 1. 核心判断

当前主要问题不只是样式不统一，而是各模块的产品形态还没有完成：

1. **模块之间没有共同的教学主线。** 思维导图、卡片、推演、练习和视频按固定顺序堆在长页面里，用户不知道先看什么，也看不出它们如何对应同一个教学步骤。
2. **所有模块被套进同一种卡片。** 算法推演需要沉浸播放器，视频需要制作与导出流程，练习需要答题模式，代码需要编辑运行环境；统一外壳反而掩盖了真实任务。
3. **算法推演没有真正渲染生成的 DSL。** 当前 `FramesPlayer` 只展示帧标题、讲解、学习目标和对象类型标签，没有调用 `VisualObjectRenderer` 呈现帧内对象。现有 `tree` 和 `graph` 还会退化成文字摘要。
4. **若干模块“名称大于能力”。** 代码沙箱不能编辑或执行代码；思维导图是缩进树；学习路径没有真正的路径图；交互 Demo 缺少宿主控制和错误恢复。
5. **生成即成品，缺少审核过程。** 只能整模块重新生成，无法对单帧、单题、单卡、单段旁白提出修改，也没有生成前后差异、版本和发布状态。
6. **前后端输出契约存在漂移。** 部分 Pydantic 模型、生成器输出与前端消费类型不一致，视觉优化建立在不稳定数据上会持续出现空白、降级或运行时错误。

所以，本轮改造应按以下顺序进行：

`统一数据契约 → 统一成果工作台 → 算法推演与视频 → 其他教学模块 → 联动与发布`

---

## 2. 从“结果集合”升级为“教学成果工作台”

### 2.1 新的信息架构

不再把十个模块垂直堆叠。改成四个任务域：

| 任务域 | 包含模块 | 用户任务 |
|---|---|---|
| 教学脉络 | 教学计划、思维导图、学习路径 | 检查知识结构和教学顺序 |
| 核心讲解 | 推演脚本、交互 Demo、代码沙箱 | 演示知识如何变化并允许试验 |
| 巩固理解 | 知识卡片、练习、常见误区、算法对比 | 解释、检查和纠正理解 |
| 发布成果 | 视频、字幕、音频、源文件、网页导出 | 预览、配置、生成和交付 |

### 2.2 桌面端框架

```text
┌────────────────────────────────────────────────────────────────────┐
│ 项目名称   已保存 · 质量 86                     预览  分享  导出   │
├───────────────┬───────────────────────────────────┬────────────────┤
│ 教学脉络      │                                   │ 当前步骤/属性 │
│  · 教学计划   │                                   │ 教学目标      │
│  · 思维导图   │          当前模块主画布            │ 讲解文本      │
│  · 学习路径   │                                   │ 参数/状态     │
│               │                                   │ 质量问题      │
│ 核心讲解      │                                   │                │
│  · 推演 14 帧 ├───────────────────────────────────┤                │
│  · 交互 Demo  │ 播放/步骤/保存/局部重新生成        │                │
│  · 代码沙箱   │                                   │                │
│ ...           │                                   │                │
└───────────────┴───────────────────────────────────┴────────────────┘
```

布局原则：

- 左侧是成果导航和状态，不是所有内容本体。
- 中间只展示当前任务的主界面。
- 右侧属性面板只在需要编辑或查看细节时出现，可收起。
- 底部操作区根据模块变化，例如播放器控制、答题提交或视频渲染。
- 用户切换模块时保留各模块当前位置、筛选、播放帧和未提交编辑。

### 2.3 移动端框架

- 顶部使用成果选择器，而非永久左栏。
- 主内容单列显示。
- 属性面板变为底部 Sheet。
- 播放、提交、保存、生成等核心行动固定在底部安全区。
- 视频制作、复杂代码编辑和批量内容审核可提示使用桌面端，但移动端必须支持查看、播放、轻量编辑和状态跟踪。

### 2.4 成果状态模型

每个模块统一具备：

```text
not_selected → queued → generating → needs_review → approved → published
                              ↘ failed
```

必须记录：

- `status`：当前状态。
- `version`：模块版本。
- `updated_at`：最后更新时间。
- `quality`：校验结果摘要。
- `dependencies`：依赖模块及其版本。
- `dirty`：是否存在未保存编辑。
- `published_version`：当前发布版本。

例如，推演脚本改变后，视频应显示“源内容已更新，需要重新渲染”，而不是继续把旧视频标成完成。

### 2.5 通用模块头部

每个模块头部只保留统一信息：

- 模块名称和一句用途说明。
- 状态：待审核、已通过、需修复、渲染中等。
- 最后更新时间和版本。
- 主操作：预览/保存/生成。
- 更多操作：查看版本、复制、删除、重新生成。

不再把“重新生成”作为每个模块最醒目的默认操作。

## 3. 算法推演与帧播放器：最高优先级重构

### 3.1 产品目标

算法推演不是帧文本浏览器，而是一个同步呈现以下信息的教学播放器：

- 当前发生的状态变化。
- 为什么要做这一步。
- 哪些对象发生了变化。
- 变化前后是什么。
- 用户可以尝试哪些参数。
- 当前步骤是否通过教学与数据校验。

### 3.2 新布局

```text
┌──────────────────────────────────────────┬────────────────────────┐
│ 画布：图/数组/树/表格/代码/内存/时间线   │ 第 06 步：松弛边 C→E   │
│                                          │ 学习目标                │
│ 对象变化使用高亮、连线和短动画           │ 讲解                    │
│                                          │ 变化：dist(E) 5 → 4     │
│                                          │ [状态表] [代码] [参数]  │
├──────────────────────────────────────────┴────────────────────────┤
│ |◀  ◀  播放/暂停  ▶  ▶|   06 / 14   ━━━━━●━━━━  1×  重播         │
└───────────────────────────────────────────────────────────────────┘
```

### 3.3 必须补齐的渲染能力

建立统一的 `SimulationStage`，实际消费 `frame.visual_objects`：

- `node / edge / graph`：真正的图渲染，不再显示“6 节点、9 边”的文字摘要。
- `array`：下标、值、比较、交换、已排序区间。
- `linked_list`：节点、指针、插入/删除/反转状态。
- `tree`：层级布局、当前路径、旋转、平衡因子。
- `table`：变化单元格、排序、行列固定。
- `code_block`：当前执行行、变量值和调用栈联动。
- `memory_block`：地址、引用、分配与释放。
- `process / timeline`：队列、时间片、阻塞/就绪/运行状态。
- `formula`：可读数学排版和替换步骤。
- `mindmap / card`：用于辅助解释，而非主画布占位。

所有对象必须支持稳定的对象 ID。跨帧相同对象保持身份，才能实现有因有果的动画，而不是整屏重绘。

### 3.4 帧数据应补充的字段

建议把帧契约扩展为：

```ts
type TeachingFrame = {
  id: string
  title: string
  learningGoal: string
  narration: string
  visualObjects: VisualObject[]
  stateSnapshot: Record<string, unknown>
  changes: ChangeRecord[]
  codeTrace?: CodeTrace
  checks: QualityCheck[]
  durationMs?: number
  chapterId?: string
}

type ChangeRecord = {
  objectId: string
  field: string
  before: unknown
  after: unknown
  reason: string
  emphasis?: "primary" | "secondary"
}
```

不要只靠前端比较两个任意 JSON 推断教学变化；生成端应明确输出变化和原因。

### 3.5 播放与探索模式

播放器区分两种状态：

#### 讲解模式

- 按既定帧顺序播放。
- 讲解、画布、状态表、代码行同步。
- 支持上一帧、下一帧、播放、暂停、跳转、速度。

#### 探索模式

- 用户修改安全参数。
- 自动播放立即暂停。
- 显示“原结果 / 当前试验结果”。
- 提供恢复默认和保存为新变体。
- 重新计算期间保留旧画面，显示局部更新状态，避免整屏空白。

### 3.6 教师编辑能力

教师应能：

- 修改单帧标题、讲解、学习目标和预计停留时间。
- 调整帧顺序并预览依赖影响。
- 锁定正确帧，局部重新生成指定帧。
- 合并过碎帧或拆分过长帧。
- 选择画布布局和重点对象。
- 查看“重新生成前后差异”后再接受新版本。

### 3.7 质量与异常反馈

帧级问题显示在对应步骤，而不是只在最后给一段质量 JSON：

- 状态不连续。
- 对象引用不存在。
- 边、节点、表格数据冲突。
- 讲解与画布变化不一致。
- 当前帧信息过多。
- 移动端无法完整呈现。

允许“只重新生成有问题的 3 帧”。

### 3.8 无障碍与移动端

- 画布之外提供同步的文本状态表和变化列表。
- 键盘快捷键：空格播放/暂停，左右箭头切帧，Home/End 首尾帧。
- 播放状态、帧切换和参数结果通过合适的 live region 播报。
- 移动端不依赖拖动画布才能完成核心学习任务。
- 时间轴和播放按钮触控尺寸至少 44×44px。

## 4. 教学视频模块：从“导出状态卡”升级为制作流程

### 4.1 当前问题

- 选择视频模块后直接按固定 `1080p / 30fps / 字幕开启`创建任务，用户没有生成前确认。
- 没有分镜、旁白、字幕和时长预览。
- 渲染状态只有排队/渲染百分比，无法说明正在处理什么。
- 没有取消、重试、后台任务提醒、版本依赖和失败恢复。
- 完成后只是原生 video 与下载链接，缺少成果管理。

### 4.2 正确的四阶段流程

#### 阶段一：视频脚本

从推演帧生成可编辑的 Storyboard：

| 镜头 | 画面 | 旁白 | 字幕 | 时长 | 状态 |
|---|---|---|---|---:|---|
| 01 | 初始化图 | “首先将源点…” | 同步字幕 | 5s | 已审核 |

用户可以：

- 预览每个镜头的静态画面或低成本动画。
- 编辑旁白与字幕。
- 调整镜头时长和顺序。
- 排除不适合视频的交互帧。
- 试听语音并检查字幕断句。

#### 阶段二：输出设置

- 比例：16:9、9:16、1:1。
- 清晰度：720p、1080p、4K。
- 帧率：默认 30fps，高动态场景才建议 60fps。
- 字幕：烧录/独立 SRT/关闭。
- 配音：无配音、选定音色、语速。
- 品牌：封面、Logo、页脚、片尾。
- 背景音乐：默认关闭，若支持必须有音量与版权说明。

设置区实时显示预计时长、文件大小区间和渲染耗时区间。

#### 阶段三：渲染任务

显示可理解的阶段进度：

`准备素材 → 生成场景 → 合成旁白 → 对齐字幕 → 编码视频 → 完成`

能力要求：

- 支持后台渲染，离开页面不丢任务。
- 支持取消尚未编码的任务。
- 网络断开后恢复轮询或事件订阅。
- 失败时指出失败阶段，并允许从该阶段重试。
- 推演版本变化后明确标记视频过期。

#### 阶段四：审核与交付

完成页包括：

- 自适应视频播放器。
- 章节/镜头列表，点击跳转。
- 字幕开关和播放速度。
- 视频、字幕、音频、Manim 源码分别下载。
- 文件格式、大小、分辨率、时长、创建时间和来源版本。
- “发现问题”可直接定位回对应推演帧或旁白。

### 4.3 视频数据契约

`VideoOutput` 不应只包含 `job_id/status/config`，应增加：

```ts
type VideoProject = {
  sourceFramesVersion: string
  storyboard: StoryboardScene[]
  settings: VideoSettings
  renderJob?: RenderJob
  artifacts?: ExportArtifact[]
  reviewStatus: "draft" | "ready" | "approved" | "outdated"
}
```

任务状态应包含阶段、可重试性、错误代码的用户映射和时间估计；内部错误日志不直接显示给普通用户。

## 5. 思维导图模块

### 当前问题

当前实现是递归缩进树，不是空间型思维导图；节点类型直接显示英文值，固定颜色不遵守主题；跨帧跳转回调在成果聚合页中也没有接通。

### 目标形态

- 默认中心主题向左右或放射展开。
- 支持折叠、展开、搜索、缩放、适应视图和全屏。
- 节点类型用中文语义：定义、核心机制、前置知识、对比、拓展、例子。
- 点击节点打开右侧详情，展示解释、相关卡片、相关帧和练习。
- 教师可重命名、增删、拖动和改变父子关系。
- 支持 PNG/PDF/结构化数据导出。
- 移动端提供“大纲视图”，而不是强迫操作大画布。

重要：导图节点、知识卡片、推演帧使用共同的 `concept_id`，点击节点才能真正联动其他模块。

## 6. 知识卡片模块

### 当前问题

所有卡片直接组成网格；单卡同时塞入定义、直觉、公式、伪代码、误区和相关帧，信息密度不稳定；缺少编辑、搜索、排序和学习状态。

### 改造方案

- 顶部提供搜索和筛选：核心概念、公式、代码、易错点、难度。
- 默认列表显示标题、摘要、类别和掌握状态；点击进入卡片详情。
- 卡片详情使用 Tab：`解释 / 例子 / 公式与代码 / 易错点 / 相关内容`。
- 教师可逐字段编辑并局部重新生成。
- 学生可标记“已理解 / 需复习”，并生成复习队列。
- “相关帧”显示可读帧名和缩略图，不显示 `f_03` 这类内部 ID。
- 支持打印、PDF、Anki/CSV 等适合卡片学习的导出形式（若后端提供）。

## 7. 小练习模块

### 当前问题

目前只有单题顺序答题和总分；缺少教师编辑、题目概览、题型策略、部分得分和重新作答分析。简答题没有可靠自动评分，却与自动计分流程混在一起。

### 两种模式

#### 教师审核模式

- 题目列表展示题型、难度、考查概念和预计用时。
- 可编辑题干、选项、答案、关键词和解析。
- 支持新增、删除、排序、复制和按概念重新生成。
- 提示答案泄漏、重复选项、歧义、难度不匹配等质量问题。

#### 学生作答模式

- 开始前展示题量、题型和预计用时。
- 顶部题目导航显示已答/未答/标记复查。
- 客观题提交后给出解释，但是否立即显示答案由教师设置。
- 简答题明确标为“参考答案/自我核对”或进入教师评分，不伪装成自动准确评分。
- 结果页按概念展示掌握情况，而不只是 `3/5`。
- 错题可跳回相关知识卡片或推演帧。

数据契约需增加评分策略、分值、接受答案、关键词权重、反馈策略和相关帧/概念 ID。

## 8. 算法对比模块

### 当前问题

当前只有算法简介卡、宽表格和一段选型建议；维度值都是字符串，难以排序、可视化或基于输入场景动态比较。

### 改造方案

- 顶部增加“比较场景”：数据规模、是否有负权、稳定性要求、内存限制等。
- 先给出一句结论：“当前场景更适合 X，因为……”。
- 使用小型量化图表展示可量化指标；定性维度仍用表格。
- 允许选择 2–4 个算法，避免移动端超宽表格。
- 提供“同一输入并排运行”，同步播放两个算法的关键步骤。
- 突出选择条件与反例，不只罗列优缺点。
- 每项结论应关联依据或适用前提，降低生成内容的绝对化表达。

数据契约应区分：

- `metric_type: numeric | ordinal | text | boolean`
- 单位、方向（越大越好/越小越好）。
- 适用条件与证据说明。
- 可用于并排演示的统一输入配置。

## 9. 常见误区模块

### 当前问题

当前通过红色错误卡展开后变成绿色正确卡，过度依赖颜色；错误文字统一删除线影响阅读，也缺少先判断再揭晓的教学过程。

### 改造方案

- 采用“你认为这句话正确吗？”的诊断交互。
- 用户先选择判断和信心程度，再揭示纠正、反例和影响。
- 误区、正确理解、反例三部分保持同时可读，不用整段删除线。
- 提供“查看对应推演步骤”和“用一个例子验证”。
- 教师模式可编辑误区、添加来源/教学备注并设置适用学习阶段。
- 结果页按概念统计误区分布，可直接生成针对性练习。

## 10. 学习路径模块

### 当前问题

当前只是按类型分组的卡片，以及一串“节点 A → 节点 B”的文字关系，并没有表达真实依赖路径，也没有学习进度和下一步建议。

### 改造方案

- 桌面使用有向路径图，清晰区分前置、当前、拓展和应用。
- 提供“推荐路径”和“全部知识网络”两种视图。
- 节点展示预计时间、掌握状态、依赖是否完成和可用学习资源。
- 点击节点可打开对应卡片、推演、练习或外部材料。
- 支持标记完成、跳过和自定义路径。
- 系统根据练习结果建议“先补前置”或“进入进阶”。
- 移动端使用纵向 Stepper，而非缩小整张关系图。

学习路径需要把 `edges` 作为一等数据，而不是展示附加文本；同时需要可选的用户进度数据层，避免把生成内容与个人学习状态混在同一个输出对象中。

## 11. 代码沙箱模块

### 当前问题

当前只是静态 `<pre>`、复制按钮、折叠答案和测试用例。所谓“可调参数”只是 Badge，代码不可编辑、不可执行、没有运行结果，因此不应继续称为沙箱。

### 目标形态

```text
┌──────────────────────────────┬──────────────────────────┐
│ 代码编辑器                    │ 任务说明/参数             │
│ 行号、语法高亮、当前执行行    │ 测试用例                  │
│                              │ 运行结果                  │
├──────────────────────────────┴──────────────────────────┤
│ 运行  单步执行  重置  查看提示                 3/5 通过 │
└─────────────────────────────────────────────────────────┘
```

能力分层：

1. **基础版**：编辑、语法高亮、复制、重置、测试用例展示。
2. **可运行版**：在安全执行环境运行，显示 stdout、错误、耗时和测试结果。
3. **教学调试版**：逐步执行，与变量、调用栈、数组/图画布同步。

要求：

- 不在主页面直接执行不受控代码。
- 运行必须有语言白名单、资源限制、超时和输出截断。
- 客户端执行只适用于安全语言/运行时；Python、Java、C++通常需要后端隔离执行服务。
- 不可执行时应改名为“代码示例”，不能用虚假的运行按钮。
- 测试失败应显示输入、期望、实际和差异。
- 完整答案的显示可由教师配置，并记录查看状态。

---

## 12. 交互 Demo 模块

### 当前问题

当前通过 Babel 编译生成代码并放入 sandbox iframe，缺少重置、全屏、宿主通信、自动高度、运行日志和主题同步；iframe 内依赖 Tailwind CDN，离线或网络受限时可能退化；错误信息也偏开发者语言。

### 改造方案

- Demo 顶栏提供：重置、全屏、打开参数、查看说明、报告问题。
- 使用受控 `postMessage` 协议传递：就绪、尺寸、状态、错误和用户事件。
- iframe 高度随内容安全调整，避免固定 400px 截断或大面积空白。
- 实际主题由宿主显式传入，不依赖系统主题猜测。
- 所需 CSS/运行时本地打包，不依赖 Tailwind Play CDN。
- 生成代码必须通过 AST/规则校验与资源限制，再进入 sandbox。
- 普通用户看到“这个演示暂时无法运行，可重试或查看静态解释”，详细堆栈仅在诊断面板中提供。
- 为关键 Demo 同时生成静态回退图和文字说明；运行失败时核心教学内容仍可用。

长期建议：交互 Demo 使用受限组件 DSL，而不是让模型任意生成 React 代码。只有需要高度自由表达的少数场景才进入代码型沙箱。

## 13. 模块之间的联动

### 13.1 统一引用模型

所有成果共享以下稳定 ID：

- `concept_id`
- `frame_id`
- `visual_object_id`
- `question_id`
- `card_id`
- `scene_id`

示例联动：

- 点击思维导图节点 → 打开对应知识卡片和相关推演帧。
- 推演停在某帧 → 右侧显示相关概念、误区和练习。
- 练习答错 → 回到相关推演步骤，再生成一道变式题。
- 修改帧旁白 → 对应视频镜头标记待更新。
- 算法对比选择同一输入 → 启动两个推演的同步播放。

### 13.2 全局搜索

项目内搜索应覆盖概念、帧标题、卡片、题目和视频字幕，结果点击后直接定位到相应模块与内容。

### 13.3 统一审核队列

教师不必逐模块寻找问题。提供审核中心：

- 3 帧状态不连续。
- 2 张卡片缺少直观解释。
- 1 道题答案存在歧义。
- 视频字幕有 4 处超长。

可按严重程度、模块和概念筛选，并逐项解决或忽略。

## 14. 数据契约与前端架构整改

### 14.1 当前契约风险

现有代码已经体现出多处漂移：

- `ComparisonOutput.algorithms` 在 Schema 中是字符串列表，而前端期望带 `name/description/pros/cons` 的对象列表。
- `PathwayOutput` Schema 使用 `prerequisites/extensions/related_topics`，前端期望 `nodes/edges/current_topic`。
- `MisconceptionItem` Schema 与前端使用的 `concept/counter_example/why_it_matters/difficulty` 不一致。
- `SandboxOutput` Schema 缺少前端使用的 `full_solution/learning_notes/time_complexity/space_complexity`。
- `ModuleOutputs` 已注明未使用且与真实输出形状不符。

这些必须先于大规模 UI 重构解决。

### 14.2 推荐做法

1. 每个模块建立唯一、版本化的后端输出模型。
2. API 返回中包含 `schema_version`。
3. 从 OpenAPI/JSON Schema 生成前端 TypeScript 类型，减少手写漂移。
4. 数据进入 UI 前通过运行时 Schema 校验并转换为 ViewModel。
5. 旧数据使用显式迁移器，不在组件中到处做类型断言。
6. 未知模块显示安全的诊断状态，不直接展示原始 JSON 给普通用户。

建议统一包络：

```ts
type ModuleArtifact<T> = {
  moduleId: string
  schemaVersion: string
  artifactVersion: string
  status: ArtifactStatus
  sourceVersions: Record<string, string>
  quality: QualitySummary
  data: T
  createdAt: string
  updatedAt: string
}
```

### 14.3 前端组件边界

- `ArtifactWorkspace`：统一成果工作台。
- `ArtifactNavigation`：模块导航、状态和问题数。
- `ArtifactHeader`：模块信息与版本操作。
- `InspectorPanel`：属性、关联内容和质量问题。
- `ReviewQueue`：统一审核列表。
- `VersionDiff`：模块或局部内容前后对比。
- 每个模块拥有独立的 `viewer/editor/empty/error`，不再由一个巨大的 switch 直接堆进卡片。

## 15. 重新生成与版本管理

“重新生成”必须从黑盒按钮变成可控操作：

- 选择范围：整个模块、选中帧、选中题目、选中卡片、选中视频镜头。
- 填写意图：更简洁、增加例子、降低难度、修正某问题等。
- 显示受影响依赖：修改推演会让视频和相关练习需要复核。
- 新结果先进入草稿，用户查看差异后选择接受或放弃。
- 已发布版本不被直接覆盖。

版本层级：

- 项目版本：教学计划及整套成果快照。
- 模块版本：例如推演 v4、视频 v2。
- 局部修订记录：例如第 6 帧旁白修改。

## 16. 性能与可靠性

- 成果模块按需加载，不同时初始化图引擎、代码编辑器、Babel 和视频播放器。
- 大型导图、帧列表和题目列表使用虚拟化或分段渲染。
- 画布与属性面板的数据更新分离，避免每次输入重绘整个图。
- 视频轮询在页面隐藏时降低频率，完成后停止；优先使用可恢复的事件订阅。
- 保存使用明确的草稿状态和失败重试，不只依赖组件本地 state。
- 交互 Demo 和代码运行失败不影响其他成果模块。
- 模块错误边界按模块隔离，单个模块崩溃不应让整个成果页白屏。

## 18. 模块级验收标准

### 算法推演

- 生成 DSL 中的所有受支持对象能真实渲染，不只显示类型名称。
- 帧切换时画布、讲解、状态、代码和变化记录同步。
- 参数修改不会被自动播放覆盖，并有重算反馈。
- 键盘和移动端可完成核心播放体验。

### 视频

- 渲染前可以检查镜头、旁白、字幕和设置。
- 离开页面后任务仍存在，回来可继续查看。
- 失败能说明阶段并从合理位置重试。
- 源推演变化后旧视频明确标记为过期。

### 思维导图与学习路径

- 关系通过真实图结构表达，并提供移动端大纲/Stepper 回退。
- 节点可跳转到相关卡片、帧和练习。

### 练习

- 教师可审核和编辑；学生可完成、复查和理解错因。
- 简答题不会被伪装成可靠自动评分。

### 代码与 Demo

- “沙箱”只有在真正可编辑且可运行时使用该名称。
- 执行受到隔离、超时、资源和输出限制。
- 运行失败时仍有可用的静态教学回退。

### 全局

- 单模块失败不影响其他成果。
- 所有模块有加载、空、错误、审核、完成和过期状态。
- Light/Dark、390px、200% 缩放、键盘和减弱动态效果通过验证。
- 重新生成保留旧版本，并允许接受或放弃差异。

## 19. 推荐的第一个开发里程碑

第一个里程碑不要同时重做十个模块，建议形成一个能证明架构正确的闭环：

1. 对齐 `frames`、`video` 及共同引用 ID 的数据契约。
2. 建立成果工作台基本框架。
3. 让生成的 `frames.visual_objects` 真正进入统一算法画布。
4. 完成帧播放器、当前变化、状态表和教师局部审核。
5. 让视频读取已审核帧形成 Storyboard，并在渲染前可编辑旁白与字幕。
6. 验证“修改一帧 → 视频标记过期 → 重新渲染 → 下载成品”的完整链路。

这个闭环完成后，知识卡片、练习、误区和路径可以接入同一套成果状态、引用、审核和版本体系，而不需要各自重复造框架。
