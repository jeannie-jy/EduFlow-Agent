# EduFlow 多主题前端视觉与交互设计

**日期：** 2026-07-19  
**状态：** 已确认，等待实施  
**适用范围：** Web 应用外壳、工作台、新建推演、计划确认、播放器、教师编辑器、模板库和导出中心

## 1. 设计结论

EduFlow 采用一套页面结构、三套可切换视觉主题。主题不是三个独立产品，也不允许维护三套业务组件；它们共享路由、DOM、领域状态、可访问性语义和交互反馈，只替换语义颜色、表面材质与环境动效参数。

三套主题为：

- **晨光 `dawn`：** 温暖纸张、矿物蓝紫、柔和阴影，强调教学亲和力。
- **深海 `deep`：** 石墨空间、光谱蓝青、局部发光，强调推演专注感。
- **画布 `canvas`：** 珍珠灰场域、清晰墨线、群青与克制珊瑚信号，强调创造与编排。

默认选择遵循系统偏好：浅色系统进入画布，深色系统进入深海；用户选择持久化后优先于系统偏好。晨光作为主动选择保留，不由系统自动映射。

## 2. 品牌资产

复用用户提供的 EduFlow“书本 + 播放三角 + 节点连线”图标信息，蓝到紫的渐变保持不变。图标与 `EduFlow` 文字组成主品牌锁定关系，也允许在侧栏收起时单独使用图标。

实施约束：

- 使用真实源图或经图像工具处理的透明背景资产，不用 CSS、字符或手绘 SVG 近似。
- 亮色与暗色主题只调整图标周围的保护区和容器，不重新着色品牌图标。
- 16–20px 场景使用 Lucide 功能图标；EduFlow 品牌图标不进入功能图标集合。

## 3. 核心体验与记忆点

核心体验是一条可见的教学推理流：

```text
教学简报 → AI 推理计划 → 可运行教学演示
```

教师不只是等待生成结果，而能看见系统如何拆解知识点、组织教学步骤并映射为可播放画面。工作台用三列空间关系表达这条链路，生成时可出现单向知识流线；静止状态仍靠对齐、编号和状态文案表达关系，不能依赖动画才能理解。

## 4. 应用外壳

桌面端由左侧全局侧栏、顶部工作区标题栏、主工作区和底部 AI 状态带组成。

- 侧栏：工作台、课程、推演项目、模板库、导出中心；首期未实现功能提供明确空状态。
- 顶栏：面包屑、保存状态、主题切换、帮助和用户菜单。
- 主题切换：使用 Shadcn Dropdown Menu 的单选组，显示主题名和视觉样片色点。
- 主区：不同路由共享最大宽度、间距与表面层级，不共享固定三列；教师编辑器按自身四区布局展开。
- 移动端：侧栏使用 Shadcn 内置 off-canvas；设置类内容放入 Sheet，画布或当前任务成为主视图。

## 5. 教师工作台

### 5.1 教学简报

简报输入区不是普通聊天框，而是教学任务编排入口：

- 大型自然语言输入支持示例提示、知识点标签和附件入口。
- 学习阶段、难度、课时、输出类型使用结构化控件。
- 主操作为“生成推演计划”，次操作为保存草稿。
- 表单采用 Shadcn `FieldGroup`、`Field`、`InputGroupTextarea`、`ToggleGroup`、`Select`、`Slider` 与 `Button`。

### 5.2 推理计划

计划是可编辑的步骤序列，不使用大量独立卡片。每个步骤是一行分组项目，包含序号、教学意图、预计时间、状态与展开设置。活动步骤显示细边强调和状态文字；已完成、当前、待处理在三主题中使用统一语义。

### 5.3 演示预览

预览突出算法画布，Dijkstra 示例包含节点、边、当前节点、已确定集合、未访问集合、距离表和讲解文本。播放器控制保持在画布下方，表格与讲解以 Tabs 或可调整面板呈现。状态不只靠颜色区分。

### 5.4 AI 状态带

底部状态带显示规划、生成、校验三阶段。运行中可使用光束或流光边框；完成、暂停和错误状态必须静止，并提供下一步操作。

## 6. 教师编辑器

教师编辑器复用播放器渲染内核，视觉布局固定为：

```text
帧列表 | 共享画布 | 属性与质量面板
              时间轴与播放控制
```

设计原则：

- 画布是视觉主角，面板通过 Resizable 组件调整，不使用叠加式玻璃卡片遮挡内容。
- 帧列表用状态点、锁定图标和质量徽章表达状态。
- 属性区按基本信息、对象、状态、动画、质量问题分组，统一使用结构化字段。
- 未保存草稿、保存中、保存成功、冲突和失败有稳定状态位置，避免 toast 成为唯一反馈。
- 局部重生成需要选择范围并明确锁定帧影响，危险操作使用 Alert Dialog。

## 7. Shadcn 基础组件

项目采用 Shadcn `base-nova` preset、Base UI primitives、CSS variables 与 Lucide 图标。Base UI 的 React peer range覆盖 React 18，因此不改变既定 React 主版本。

基础映射：

| 场景 | Shadcn 组件 |
|---|---|
| 外壳 | Sidebar、SidebarInset、Breadcrumb、DropdownMenu、Avatar |
| 表单 | Field、FieldGroup、InputGroup、ToggleGroup、Select、Slider、Switch |
| 工作流 | Item、Badge、Separator、Progress、Collapsible、ScrollArea |
| 画布周边 | Resizable、Tabs、Table、Tooltip、Popover、ButtonGroup、Sheet |
| 系统反馈 | Alert、Skeleton、Spinner、Empty、Sonner |

所有按钮、表单、卡片、导航、弹窗、抽屉、表格、空状态和加载状态均由 Shadcn 提供。业务组件可组合和布局 Shadcn，但不得用 Aceternity、Magic UI 或 Uiverse 的同类基础控件替换。

## 8. 动效与外部来源

全站允许约 6–10 个可复用特效组件，集中于 `src/components/effects/`。首批候选池：

- Magic UI：Animated Grid Pattern、Animated Beam、Border Beam 或 Shine Border。
- Aceternity UI：Spotlight、Tracing Beam、Text Generate Effect。
- Uiverse：一个 MIT 许可的轻量 Agent 处理中微型装饰加载效果。

采用规则：

- 同屏持续显著动效最多两个。
- 页面入场、hover 和 focus 等短暂反馈不计入持续预算。
- 深海 Spotlight、晨光纸张纹理和画布网格互斥，只加载当前主题效果。
- 动画服务于层级、流程和状态，不做无意义漂浮或背景噪声。
- `prefers-reduced-motion` 下关闭背景漂移、光束移动和逐字揭示，保留立即呈现的文本状态。
- 每个外部文件记录来源 URL、许可证、依赖和本地改动。

## 9. 主题技术模型

主题 id 为 `dawn | deep | canvas`，写入 `<html data-theme>`。`ThemeProvider` 只负责读取、设置、持久化与系统偏好监听；页面不得判断主题 id 后返回不同业务组件。

持久化键：`eduflow-theme`。首次渲染前的内联脚本读取该键并设置 `data-theme`，避免 hydration 前闪色。切换主题不重置路由、表单、播放器、草稿或 Agent 状态。

完整语义颜色、字体、圆角、间距、响应式和动效令牌见 `design-system/eduflow/MASTER.md`。

## 10. 可访问性与响应式

- 正文对比度不低于 4.5:1；大字与非文本边界不低于 3:1。
- 所有交互可键盘完成，焦点环在三个主题中均可见。
- AI 进度使用礼貌级 live region；错误包含明确恢复操作。
- 颜色状态同时配合文字、图标、形状或线型。
- 触控目标最小 44×44px。
- 在 375、768、1024、1440px 验证，无横向溢出和固定导航遮挡。

## 11. 验收标准

- 三主题可即时切换并持久化，刷新无明显闪色。
- 三主题使用同一应用结构和业务组件，切换后编辑状态不丢失。
- EduFlow 品牌图标在亮暗主题中清晰且保持原渐变。
- 工作台清楚表达“简报 → 计划 → 演示”的核心流程。
- 教师编辑器保持画布优先、面板可调整、状态可观察。
- Shadcn 是唯一基础组件来源；外部库只用于审核过的装饰效果。
- reduced-motion、键盘、焦点、对比度与四个目标宽度验收通过。
