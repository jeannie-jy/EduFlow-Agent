# EduFlow 宣传与认证界面设计规格

**日期：** 2026-07-19  
**状态：** 已确认视觉方向，等待实施  
**适用范围：** Web 宣传首页、登录页、注册页，以及三者共享的品牌视觉与动效基础

## 1. 设计目标

以用户提供的明亮智慧教育界面为构图基准，以靛青色作为 EduFlow 的核心品牌色，为产品建立一套连续的首次访问体验：访客先理解“把抽象计算机科学知识变成可交互推演”的产品价值，再通过登录或注册进入工作台。

本轮只实现前端体验和模拟认证反馈，不接入真实用户系统、数据库或第三方登录服务。现有后端、数据库和教学推演业务逻辑均不修改。

## 2. 视觉方向

采用已确认的“高还原延展”方向。

- 保留参考图的大面积柔白背景、深靛文字、半透明悬浮面板、柔和高光和宽松布局；渐变由靛青主导，以冰蓝提亮、少量紫色收边。
- 将参考图的“播放图标 + 打开的书”扩展为 EduFlow 的“知识进入书页、被拆解为可播放推演”的品牌隐喻。
- 视觉中心使用真实生成的智慧书籍资产；不得使用 CSS 图形、字符、手绘 SVG 或占位图模拟。
- 功能图标使用统一的现成图标库，品牌图标与主视觉插图使用真实图像资产。
- 中文内容优先，产品名保留 `EduFlow`；展示字体需要同时覆盖中文和拉丁字符，并以清晰、圆润、现代为准。

建议颜色令牌：

| 用途 | 色值或范围 |
|---|---|
| 主文字 | `#11183F` |
| 次文字 | `#657096` |
| 核心靛青 | `#3F51E8` |
| 深靛青 | `#2635B8` |
| 明亮靛青 | `#6475FF` |
| 冰蓝高光 | `#7DDCFF` |
| 紫色收边 | `#7557F6`，仅用于渐变末端与局部反光 |
| 页面底色 | `#F9FAFF` 到 `#F2F4FF` |
| 玻璃边界 | 白色 55%–80% 透明度 |

## 3. 信息架构与路由

公开访问包含三条独立路由：

- `/`：宣传首页。
- `/login`：登录页。
- `/register`：注册页。

宣传页顶部和首屏按钮可以进入登录或注册。认证页可以在登录与注册间互相跳转，并可返回首页。模拟认证成功后进入 `/app`；若工作台尚未实施，则 `/app` 显示明确的轻量占位状态，而不是死链接。

移动端保留相同路由与内容顺序，不建立另一套页面结构。

## 4. 宣传首页

### 4.1 顶部导航

顶部为透明或轻微雾化的悬浮导航，包含 EduFlow 品牌、产品能力、使用场景、工作方式和登录/免费开始操作。

- 桌面端导航在首屏顶端保持宽松横向布局。
- 页面滚动后背景透明度与阴影略微增强，保证文字可读。
- 移动端折叠为菜单按钮，展开后必须可键盘操作并可关闭。

### 4.2 首屏叙事

左侧文案明确表达产品价值：

> 让知识动起来。让理解自然发生。

辅助说明强调 EduFlow 能把算法、数据结构和系统过程转化为逐帧、可交互、可回退的教学推演。

主要操作为“免费开始”，进入注册页；次要操作为“查看如何工作”，滚动到工作方式区域。按钮、导航和滚动锚点均需真实可用。

右侧是智慧书籍主视觉。书本上方的播放符号和知识节点采用真实生成资产或图标组合，但不得用代码绘制参考图中的主体插画。

### 4.3 悬浮信息卡

主视觉周围布置三张小型功能卡：

- AI 教学规划：自动拆解知识与学习目标。
- 交互式推演：支持播放、暂停、回退与参数调整。
- 学习进度：记录理解轨迹与关键难点。

卡片保持低信息密度，以错开的轻微浮动形成空间层次；移动端只保留一至两张或转为静态标签，避免遮挡主体。

### 4.4 能力概览

首屏下方延续参考图的三列卡片，但内容调整为 EduFlow 的核心能力：

1. 从自然语言到教学计划。
2. 从计划到逐帧推演。
3. 从交互体验到教学视频。

每张卡片包含一个真实图标、简短说明和小型产品界面预览。预览使用前端界面组件或真实生成图像，不使用无意义占位块。

### 4.5 工作方式与最终转化

后续区域以三步流程串起“提出问题 → 生成推演 → 探索与导出”，并以一个简洁的最终行动区结束。第一轮不增加定价、客户 Logo 墙、博客或复杂页脚，避免超出当前产品阶段。

## 5. 登录与注册体验

### 5.1 共享结构

认证页采用桌面端左右分栏：左侧为动态智慧书籍与品牌价值短句，右侧为清晰的表单面板。背景、光晕和书籍与宣传页一致，使跳转看起来像同一场景的镜头推进。

在窄屏设备上，表单优先排列；书籍缩小为顶部品牌场景或低透明背景，不占用首屏主要操作空间。

### 5.2 登录页

字段包括邮箱和密码，提供显示/隐藏密码、记住我和忘记密码入口。主要操作为“登录 EduFlow”，次要入口为“创建账号”。

表单行为：

- 使用原生语义标签和浏览器自动填充提示。
- 邮箱格式和必填项在本地验证。
- 提交后显示短暂加载状态，再进入成功状态并导航到 `/app`。
- 模拟错误使用稳定的表单内提示，不只依赖浮层消息。

### 5.3 注册页

字段包括昵称、邮箱、密码和确认密码，并提供服务条款确认。主要操作为“创建免费账号”，次要入口为“已有账号，直接登录”。

密码要求在用户输入时提供可读反馈：至少 8 位，并同时包含字母和数字；确认密码必须一致。提交成功后展示简短欢迎反馈，再导航到 `/app`。

第三方登录按钮本轮不实现，避免制造不可用入口。

## 6. 动效系统

动效是本项目的记忆点，但必须服务于“知识被唤醒并流动”的叙事。

### 6.1 书页动态

- 将主视觉资产拆分为书本主体和少量前景书页层，或生成适合分层呈现的透明资产。
- 前景书页围绕书脊做 2–4 度的缓慢摆动，并带极小的上下位移。
- 不使用整本书大幅旋转；书脊和主要轮廓需要稳定，避免廉价漂浮感。
- 页面首次进入时执行一次由闭合层次到舒展状态的柔和展开，之后进入低幅度循环。

### 6.2 空间层次

- 光粒以不同速度缓慢上升或横向漂移。
- 知识流线从左下向书本聚拢，再向右上散开；线条应轻薄且低对比度。
- 悬浮卡片使用不同相位和幅度，避免同步机械运动。
- 桌面端允许基于指针位置产生不超过 8px 的视差；触屏设备不启用指针视差。

### 6.3 页面与表单反馈

- 宣传页各区域进入视口时使用轻微上移和透明度变化，不采用大幅弹跳。
- 宣传页进入认证页时，书籍视觉保持相近位置与尺度关系，形成连续镜头感。
- 登录与注册切换时只替换表单内容，容器尺寸平滑过渡。
- 输入聚焦、验证、加载与成功均有清晰但短促的视觉反馈。

### 6.4 动效约束

- 同一视口最多保留两类明显持续动画：书页动态与背景知识流。
- `prefers-reduced-motion: reduce` 时关闭书页循环、粒子漂移、视差和滚动揭示，保留立即呈现的静态最终状态。
- 动画不得阻塞点击、滚动、输入或页面加载。
- 主视觉资产优先使用 WebP 或优化 PNG，并避免在低性能移动设备上加载过多透明大图。

## 7. 前端结构

前端使用既定的 React、TypeScript 与 Vite 方向，并复用项目计划中的 Shadcn 基础组件规则。建议模块边界如下：

```text
app/router
├── public/LandingPage
├── auth/LoginPage
├── auth/RegisterPage
└── app/AppEntryPlaceholder

shared
├── brand/EduFlowBrand
├── layout/PublicHeader
├── auth/AuthShell
├── auth/AuthFormField
└── effects/BookHeroScene
```

`BookHeroScene` 只负责品牌资产、书页分层和环境动效；页面文案与按钮不放入该组件。`AuthShell` 只负责共享布局和视觉连续性；登录与注册表单分别管理自己的字段和验证。路由层负责页面切换，认证表单不直接依赖后端 API。

## 8. 状态与数据流

- 导航和行动按钮通过客户端路由切换页面。
- 登录与注册字段使用组件本地状态或表单工具管理。
- 校验按字段触发，并在提交时执行完整校验。
- 模拟提交遵循 `idle → validating → submitting → success | error` 状态序列。
- 成功状态导航到 `/app`，错误状态保留输入并将焦点移到首个错误字段。
- 动效偏好来自系统媒体查询，不写入业务状态。

未来接入真实认证时，只替换提交函数与会话处理，不改变表单组件、页面结构或视觉反馈契约。

## 9. 错误与边界处理

- 未知公开路由显示可返回首页的 404 状态。
- 登录失败、邮箱已存在等服务端错误预留表单级错误区域。
- 图像加载失败时保留品牌色背景和可理解的文字内容，不显示破损图片图标。
- 慢速设备上可以降低粒子数量，主操作和表单不等待动画初始化。
- 认证按钮提交中禁止重复触发，但页面导航和错误恢复必须可用。

## 10. 响应式与可访问性

- 目标宽度：375、768、1024、1440 和参考图对应的宽屏比例。
- 页面不得产生非预期横向滚动，导航与表单主要操作不得被裁切。
- 所有输入有可见标签、说明和错误关联；焦点环在浅色渐变背景上仍清晰。
- 文字与背景对比度遵守 WCAG AA；状态不能只靠颜色表达。
- 触控目标至少 44×44px，移动端表单按钮占满可用宽度。
- 装饰图像使用空替代文本，承载产品含义的主视觉提供简洁替代说明。

## 11. 验证与验收

### 11.1 功能验收

- 首页导航、锚点、登录和注册入口均可用。
- 登录与注册可互相跳转并返回首页。
- 表单完成本地校验，加载、错误和成功状态可见。
- 成功提交能够到达 `/app`。
- 浏览器刷新任一公开路由后仍可正确渲染。

### 11.2 视觉验收

- 同一宽屏视口下，与参考图对比整体留白、首屏比例、主视觉重心、靛青色层次、文字换行和卡片密度。
- 宣传页和认证页的书籍资产、光影语言与动效节奏保持一致。
- 不使用 CSS 绘图、字符或占位图冒充书籍、Logo 和可见插画。
- 书页动态自然，无明显切边、透明光晕、抖动或锚点漂移。

### 11.3 工程验收

- 类型检查、单元测试和生产构建通过。
- 覆盖登录与注册的主要校验逻辑和路由跳转。
- 使用真实浏览器检查主要交互、控制台错误和关键响应式视口。
- 完成参考图与实现截图的同视口视觉对比；所有 P0、P1 和 P2 问题修复后，`design-qa.md` 的最终结果必须为 `passed`。

## 12. 本轮不包含

- 真实账号、会话、验证码、邮件确认、密码找回或单点登录。
- 付费、订阅、价格页、客户案例和内容管理后台。
- 教学工作台、播放器和教师编辑器的完整业务实现。
- 深色主题或多主题切换；公开页面先聚焦参考图对应的明亮品牌主题。
