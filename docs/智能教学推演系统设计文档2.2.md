## 1. 项目定位与核心价值

### 1.1 一句话定位

> **面向计算机科学教育的自主 Agent 教学推演系统**——Agent 自主规划教学策略、动态编排多模态渲染资源、通过反思循环持续优化输出质量，将抽象 CS 概念转化为可交互的逐帧推演序列，并支持导出为 Manim 渲染的高清视频。

### 1.2 核心价值主张

| 维度 | 传统方案 | EduFlow-Agent |
|------|----------|---------------|
| **生成方式** | 人工制作动画 / 录制PPT | Agent 自主规划→生成→验证→反思 |
| **交互性** | 被动观看视频 | 可暂停、修改参数、实时预览每一步 |
| **泛化能力** | 每个算法需单独制作 | Few-shot 模板 + 自主 Planning 覆盖新算法 |
| **质量保障** | 人工审核 | Validator + Reflection + Human Feedback 三重保障 |
| **输出形式** | 单一视频文件，无法交互 | 交互式 Web 推演（主路径）+ Manim 视频导出（辅助路径） |
| **系统架构** | 单体应用 | Multi-Agent + MCP Server + Agent Runtime |

### 1.3 自主性级别

```
L1: 固定脚本播放              → 传统教育视频
L2: 参数化模板填充            → PPT 模板
L3: LLM 单次生成 + 人工修正    → 当前大多数 AI 教育工具
L4: Agent 自主规划 + Human审批  → EduFlow-Agent (本系统)
L5: 全自主 Agent              → 未来目标
```

本系统定位 **L4：Copilot 模式（Human-in-the-loop）**。Agent 拥有自主决策权（选择工具、调整计划、发起反思），但关键节点需要人类确认，且接受人类反馈作为学习信号。

### 1.4 与其他 Agent 范式的对齐

| 范式 | 本系统对应实现 |
|------|---------------|
| **OpenAI Agents SDK** | Planner Agent + Tool Handoff 机制 |
| **Anthropic MCP** | Renderer / Memory / Knowledge 均封装为 MCP Server |
| **LangGraph** | Task Graph + 条件边 + Reflection Loop |
| **Google ADK** | Agent-to-Agent (A2A) 通信协议 |
| **ReAct** | Thought→Action→Observation 循环 |
| **Plan-and-Execute** | Planner 生成 Task DAG → Executor 逐步执行 |

## 2. 需求分析与场景定义

### 2.1 核心目标

将抽象的计算机科学概念（多线程并发、进程树调度、B+树索引、图算法、编译原理等）转化为**可交互的动态推演序列**。不仅生成"视频"，更生成"可交互的步骤"。

### 2.2 目标用户

| 用户角色 | 核心需求 | 使用模式 |
|----------|---------|---------|
| **备课教师** | 快速生成课件演示，自定义教学节奏 | 输入概念 → 审核 Agent 规划 → 微调参数 → 课堂展示 |
| **CS 专业学生** | 直观理解底层逻辑，可反复推演 | 输入疑问 → 跟随 Agent 分步推演 → 修改输入验证理解 |
| **教学研究员** | 对比不同教学策略效果 | 批量生成 → A/B Test → 评估学习效果 |

### 2.3 系统边界

- ✅ **做：** CS 算法与数据结构的可视化推演、交互式分步教学、自动教学策略规划、基于 Manim 的教学视频导出（辅助功能）
- ❌ **不做：** 实拍人像视频、泛娱乐内容、非 CS 领域的通用视频生成
- ⚠️ **核心约束：** 大模型仅负责"逻辑推导"和"渲染指令生成"，最终画面由确定性的渲染引擎接管。Manim 视频导出为 RenderScript 的可选输出路径，走独立的后端渲染管线，不影响主交互流程。

### 2.4 场景示例

**场景：用户输入"演示 AVL 树的插入过程"**

```
Planner Agent 自主决策：
  Thought: AVL 树涉及插入和旋转，需要先建立基础概念，再逐步展示
  Action: query_knowledge_base("AVL树 插入 旋转 教学")
  Observation: 找到 3 个相关模板，包含 LL→RR→LR→RL 四种旋转

  Thought: 用户可能不熟悉四种旋转，计划分 5 步展开，先讲解再演示
  Action: build_task_graph({
    steps: [
      {id:1, type:"concept_intro", deps:[], desc:"AVL树定义与平衡因子"},
      {id:2, type:"animation", deps:[1], desc:"简单插入（无旋转）"},
      {id:3, type:"animation", deps:[2], desc:"LL旋转演示"},
      {id:4, type:"animation", deps:[2], desc:"RR旋转演示"},
      {id:5, type:"animation", deps:[3,4], desc:"LR/RL复合旋转"},
      {id:6, type:"quiz", deps:[5], desc:"交互式练习"}
    ]
  })

  Thought: 计划已构建，提交给用户审核
  → [Human Approval]
  → Coder Agent 逐帧生成
  → Validator 校验
  → Reflection 优化
  → Renderer 执行
```

### 3.2 架构原则

| 原则 | 说明 | 实现方式 |
|------|------|---------|
| **LLM for Thinking, not Doing** | LLM 只负责决策与规划，不直接操作 DOM/文件/数据库 | Agent 输出 DSL，Engine 执行 |
| **Single Responsibility** | 每个 Agent 只做一件事 | Planner→Coder→Reflection 职责分离 |
| **Tool as First-Class Citizen** | 一切能力皆 Tool，Agent 自主决定调用时机 | MCP 协议统一封装 |
| **Observability by Default** | 所有决策、调用、失败均记录轨迹 | OpenTelemetry + 自定义 Trajectory Logger |
| **Human in the Loop** | 关键决策需人类确认，反馈形成学习闭环 | Approval Gateway + Feedback Collector |
| **Graceful Degradation** | 单点失败不导致全局崩溃 | Retry → Reflection → Fallback → Human 四级降级 |
| **Multi-Format Output** | 同一份 RenderScript 驱动双路径渲染——交互式 Web（主）与 Manim 视频（辅），共享核心逻辑，差异化输出 | RenderScript → Adapter → Target Renderer |

### 3.3 视频导出管线 (Video Export Pipeline)

#### 设计理念

> Manim 视频导出是 RenderScript 的**可选辅助输出路径**。Agent 仍然只生成一份 RenderScript JSON，由 Adapter 层将其翻译为 Manim Scene，经 Cairo/OpenGL 后端逐帧渲染后，由 FFmpeg 合成为 MP4。Agent 无需感知视频导出细节——它只关心"教学逻辑是否正确"，而非"输出介质是什么"。

```
                    ┌──────────────────────────┐
                    │     RenderScript JSON     │
                    │   (Coder Agent 唯一输出)    │
                    └────────────┬─────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              │                  │                  │
    ┌─────────▼─────┐   ┌───────▼───────┐   ┌───────▼───────┐
    │ Web Renderer  │   │ Manim Adapter │   │ 未来扩展       │
    │ (React/Canvas)│   │ (Python)      │   │ (GIF/SVG/PPT) │
```

#### RenderScript → Manim 映射规则

Coder Agent 输出的 `RenderAction` 与 Manim 原生能力天然对齐：

| RenderAction | Manim 对应 | 说明 |
|-------------|-----------|------|
| `CREATE_NODE` | `Circle()` / `Rectangle()` / `Text()` + `Create()` | 创建 Mobject 并播放创建动画 |
| `UPDATE_NODE` | `obj.become()` / `Transform()` | 节点状态变换 |
| `DELETE_NODE` | `FadeOut()` / `Uncreate()` | 节点移除 |
| `HIGHLIGHT_NODE` | `Indicate()` / `FocusOn()` / `SurroundingRectangle()` | 高亮强调 |
| `CREATE_EDGE` | `Arrow()` / `Line()` + `Create()` | 创建连线 |
| `TRAVERSE_EDGE` | `ShowPassingFlash()` / `MoveAlongPath()` | 边遍历动画 |
| `HIGHLIGHT_PATH` | 组合 `Flash()` / `AnimationGroup()` | 路径高亮 |
| `ROTATE` | `Rotate()` / `ApplyMethod()` | AVL 旋转等操作 |
| `SWAP` | `Swap()` / `CyclicReplace()` | 节点交换 |
| `COMPARE` | 左右布局 + `AnimationGroup()` 同步播放 | 对比展示 |
| `SHOW_LABEL` | `Text()` / `MathTex()` + `Write()` | 标注文字 |
| `SHOW_CODE` | `Code()` + 逐行 `Write()` | 代码展示 |
| `PAUSE` | `self.wait()` | 停顿 |
| `TRANSITION` | `FadeTransform()` / `ReplacementTransform()` | 场景过渡 |

#### Manim Renderer 核心实现

```python
# manim_renderer.py — RenderScript → Manim Scene → MP4
from manim import *
from typing import Optional
import subprocess
import json

class RenderScriptScene(Scene):
    """将 RenderScript JSON 翻译为 Manim Scene"""

    def __init__(self, render_script: dict, config: "VideoExportConfig", **kwargs):
        super().__init__(**kwargs)
        self.render_script = render_script
        self.export_config = config
        self.mobject_registry: dict[str, Mobject] = {}  # 节点 ID → Mobject 映射

    def construct(self):
        """主渲染入口 — 逐帧翻译 RenderAction 序列"""
        for frame in self.render_script["frames"]:
            self.render_frame(frame)

    def render_frame(self, frame: dict):
        """渲染单个 RenderFrame"""
        animations = []
        for action in frame["actions"]:
            anim = self._dispatch_action(action)
            if anim:
                animations.append(anim)

        if animations:
            self.play(AnimationGroup(*animations))
        elif frame.get("duration_ms", 0) > 0:
            self.wait(frame["duration_ms"] / 1000.0)

    def _dispatch_action(self, action: dict) -> Optional[Animation]:
        """将单个 RenderAction 分发到对应 Manim 方法"""
        action_type = action["action"]
        target = action.get("target", "")
        params = action.get("params", {})

        handlers = {
            "create_node":       self._create_node,
            "update_node":       self._update_node,
            "delete_node":       self._delete_node,
            "highlight_node":    self._highlight_node,
            "create_edge":       self._create_edge,
            "traverse_edge":     self._traverse_edge,
            "highlight_path":    self._highlight_path,
            "rotate":            self._rotate,
            "swap":              self._swap,
            "compare":           self._compare,
            "show_label":        self._show_label,
            "show_code":         self._show_code,
            "show_tooltip":      self._show_label,       # tooltip 降级为 label
            "pause":             self._pause,
            "transition":        self._transition,
            "wait_for_input":    self._pause,            # 视频中降级为 pause
            "move_node":         self._move_node,
        }

        handler = handlers.get(action_type)
        if handler:
            return handler(target, params)
        return None

    # ── Action Handlers ─────────────────────────────────

    def _create_node(self, target: str, params: dict) -> Animation:
        label = params.get("label", "")
        node_type = params.get("node_type", "circle")
        color = params.get("color", "#58A6FF")
        position = self._parse_position(params.get("position", [0, 0, 0]))

        if node_type == "circle":
            mob = Circle(radius=0.4, color=color, fill_opacity=0.15)
        elif node_type == "rectangle":
            mob = Rectangle(width=1.2, height=0.7, color=color, fill_opacity=0.15)
        else:
            mob = Circle(radius=0.4, color=color, fill_opacity=0.15)

        text = Text(label, font_size=20, color=WHITE).move_to(mob.get_center())
        group = VGroup(mob, text).move_to(position)
        self.mobject_registry[target] = group
        return Create(group)

    def _create_edge(self, target: str, params: dict) -> Animation:
        from_id = params.get("from", "")
        to_id = params.get("to", "")
        directed = params.get("directed", True)

        from_mob = self.mobject_registry.get(from_id)
        to_mob = self.mobject_registry.get(to_id)
        if not from_mob or not to_mob:
            return None

        if directed:
            edge = Arrow(from_mob.get_center(), to_mob.get_center(),
                         buff=0.3, color=GRAY, stroke_width=2)
        else:
            edge = Line(from_mob.get_center(), to_mob.get_center(),
                       color=GRAY, stroke_width=2)

        self.mobject_registry[target] = edge
        return Create(edge)

    def _highlight_node(self, target: str, params: dict) -> Animation:
        mob = self.mobject_registry.get(target)
        if not mob:
            return None
        color = params.get("color", "#FFD700")
        return Indicate(mob, color=color, scale_factor=1.2)

    def _rotate(self, target: str, params: dict) -> Animation:
        mob = self.mobject_registry.get(target)
        if not mob:
            return None
        angle = params.get("angle", PI / 2)
        direction = params.get("direction", "left")
        angle = angle if direction == "left" else -angle
        return Rotate(mob, angle=angle, about_point=mob.get_center())

    def _swap(self, target: str, params: dict) -> Animation:
        a = self.mobject_registry.get(params.get("node_a", ""))
        b = self.mobject_registry.get(params.get("node_b", ""))
        if not a or not b:
            return None
        return CyclicReplace(a, b)

    def _show_label(self, target: str, params: dict) -> Animation:
        text = params.get("text", "")
        position = self._parse_position(params.get("position", [0, 2, 0]))
        label = Text(text, font_size=24, color=WHITE).move_to(position)
        return Write(label)

    def _show_code(self, target: str, params: dict) -> Animation:
        code_str = params.get("code", "")
        language = params.get("language", "python")
        code_block = Code(code=code_str, language=language,
                          font_size=18, line_spacing=0.6)
        return Write(code_block)

    def _pause(self, target: str, params: dict) -> None:
        duration = params.get("duration_ms", 1000) / 1000.0
        self.wait(duration)
        return None

    def _transition(self, target: str, params: dict) -> Animation:
        wipe_direction = params.get("direction", "right")
        directions = {"right": RIGHT, "left": LEFT, "up": UP, "down": DOWN}
        direction = directions.get(wipe_direction, RIGHT)
        # 对整个场景做淡出 + 新帧淡入
        return FadeOut(*self.mobjects, shift=direction)

    def _move_node(self, target: str, params: dict) -> Animation:
        mob = self.mobject_registry.get(target)
        if not mob:
            return None
        new_pos = self._parse_position(params.get("position", [0, 0, 0]))
        return mob.animate.move_to(new_pos)

    def _delete_node(self, target: str, params: dict) -> Animation:
        mob = self.mobject_registry.pop(target, None)
        return FadeOut(mob) if mob else None

    def _update_node(self, target: str, params: dict) -> Animation:
        mob = self.mobject_registry.get(target)
        if not mob:
            return None
        new_label = params.get("label")
        new_color = params.get("color")
        if new_label and hasattr(mob, 'become'):
            new_mob = Circle(radius=0.4, color=new_color or "#58A6FF",
                             fill_opacity=0.15)
            self.mobject_registry[target] = new_mob
            return Transform(mob, new_mob)
        return None

    def _traverse_edge(self, target: str, params: dict) -> Animation:
        edge = self.mobject_registry.get(target)
        if not edge:
            return None
        return ShowPassingFlash(edge.copy().set_color(YELLOW), time_width=0.3)

    def _highlight_path(self, target: str, params: dict) -> Animation:
        edge_ids = params.get("edges", [])
        anims = []
        for eid in edge_ids:
            edge = self.mobject_registry.get(eid)
            if edge:
                anims.append(Flash(edge, color=YELLOW, line_length=0.2))
        return AnimationGroup(*anims) if anims else None

    def _compare(self, target: str, params: dict) -> Animation:
        left_target = params.get("left", "")
        right_target = params.get("right", "")
        left = self.mobject_registry.get(left_target)
        right = self.mobject_registry.get(right_target)
        if left and right:
            left.generate_target().shift(LEFT * 3)
            right.generate_target().shift(RIGHT * 3)
            return AnimationGroup(
                MoveToTarget(left), MoveToTarget(right)
            )
        return None

    # ── Helpers ─────────────────────────────────────────

    def _parse_position(self, pos) -> np.ndarray:
        """将 [x, y] 或 [x, y, z] 转为 np.array"""
        if isinstance(pos, (list, tuple)):
            if len(pos) == 2:
                return np.array([pos[0], pos[1], 0.0])
            return np.array(pos)
        return np.array([0, 0, 0])


class ManimVideoRenderer:
    """Manim 视频渲染器 — RenderScript JSON → 视频文件"""

    def __init__(self, config: "VideoExportConfig"):
        self.config = config

    def render(self, render_script: dict) -> str:
        """
        将 RenderScript 渲染为 MP4 视频

        返回：输出文件路径
        """
        import tempfile, os

        # 1. 将场景脚本写入临时文件
        with tempfile.NamedTemporaryFile(
            mode='w', suffix='.py', delete=False, encoding='utf-8'
        ) as f:
            f.write(self._generate_scene_script(render_script))
            script_path = f.name

        # 2. 调用 manim CLI 渲染
        output_dir = self.config.output_dir or "./output/videos"
        os.makedirs(output_dir, exist_ok=True)

        cmd = [
            "manim",
            "-p" if self.config.preview else "",
            f"-q{self.config.quality}",      # -ql / -qm / -qh / -qk
            "--format", self.config.format,   # mp4 / gif / webm
            "--fps", str(self.config.fps),
            "--resolution", self.config.resolution,  # e.g. "1920,1080"
            script_path,
            "RenderScriptScene",
            "-o", output_dir,
        ]
        cmd = [c for c in cmd if c]  # 过滤空字符串

        result = subprocess.run(cmd, capture_output=True, text=True, timeout=600)

        # 3. 清理临时脚本
        os.unlink(script_path)

        if result.returncode != 0:
            raise RuntimeError(f"Manim 渲染失败:\n{result.stderr}")

        # 4. 返回输出路径
        video_filename = f"RenderScriptScene.{self.config.format}"
        return os.path.join(output_dir, video_filename)

    def _generate_scene_script(self, render_script: dict) -> str:
        """生成完整的 Manim 场景 Python 脚本"""
        import json
        script_json = json.dumps(render_script, ensure_ascii=False, indent=2)
        config_json = json.dumps(self.config.__dict__, ensure_ascii=False)

        return f'''
```

#### 使用场景对照

| 场景 | 推荐路径 | 理由 |
|------|---------|------|
| **课堂实时教学** | 交互式 Web | 教师可随时暂停、调整参数、回答学生提问 |
| **预习/复习** | 视频导出 | 学生可离线观看，反复回放关键步骤 |
| **MOOC/在线课程** | 视频导出 | 上传到视频平台，触达更多学习者 |
| **教学研讨** | 交互式 Web | 实时演示不同输入/策略的差异 |

| **批量评估对比** | 视频导出 | EduCS-Benchmark 中对比不同 Agent 策略的可视化效果 |

#### 与主流程的关系

1. **Agent 无感知**：Coder Agent 只生成 RenderScript JSON，不区分输出目标。视频导出是 RenderScript 的消费者之一。
2. **异步执行**：视频渲染在独立 Docker 容器中运行，不阻塞交互式 Web 主路径。渲染完成后通过 WebSocket/回调通知用户下载。
3. **共享校验**：视频导出前复用 Validator Agent 的 Schema 校验结果，确保输入合法。
4. **独立降级**：视频渲染失败不影响 Web 交互渲染，反之亦然。两条路径各自拥有独立的降级策略。

## 4. Agent 运行时与决策循环

### 4.1 核心区别：Agent vs Workflow

```
┌─────────────────────────────────────────────────────────────────┐
│                    WORKFLOW (固定管道)                            │
│                                                                 │
│  Input → Step1 → Step2 → Step3 → Output                        │
│                                                                 │
│  特点：路径固定，无自主决策，LLM 只在每个 Step 内部被调用          │
│  问题：无法应对意外情况，缺乏灵活性，不是 Agent                     │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    AGENT LOOP (自主决策循环)                      │
│                                                                 │
│                  ┌──────────────┐                               │
│                  │   Thought    │←──────────────┐              │
│                  └──────┬───────┘               │              │
│                         │                       │              │
│                  ┌──────▼───────┐               │              │
│                  │   Action     │               │              │
│                  │ (Tool调用或  │               │              │
│                  │  子Agent委托)│               │              │
│                  └──────┬───────┘               │              │
│                         │                       │              │
│                  ┌──────▼───────┐               │              │
│                  │  Observation │───────────────┘              │
│                  │ (结果/失败/   │                               │
│                  │  人类反馈)    │                               │
│                  └──────────────┘                               │
│                                                                 │
│  特点：LLM 自主决定下一步做什么，选择哪个工具，何时结束             │
│  关键：Decision-Making 而非 Execution-Only                       │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 Agent Runtime 选型

**主 Runtime：LangGraph**

| 考量 | LangGraph | OpenAI Agents SDK | AutoGen | 自研 |
|------|-----------|-------------------|---------|------|
| **Planning 能力** | ✅ StateGraph + Conditional Edges | ⚠️ Handoff 模式 | ✅ GroupChat | 🟡 需自行实现 |
| **图/树结构原生支持** | ✅ 内置图遍历 | ❌ Linear | ❌ RoundRobin | 🟡 |
| **Human-in-the-Loop** | ✅ interrupt() / Command | ⚠️ | ✅ | 🟡 |
| **Streaming** | ✅ Native | ✅ | ⚠️ | 🟡 |
| **生态成熟度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐ |
| **生产中可维护性** | 高 | 中 | 中 | 低 |

**决策：** 主 Runtime 使用 **LangGraph**（StateGraph + 条件边），同时通过适配器模式抽象 Runtime 接口，确保未来可低成本迁移到其他框架。

### 4.3 主 Agent Loop 定义

```python
from typing import TypedDict, Literal, Annotated, Sequence
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.prebuilt import ToolNode
import operator

# ── State Definition ──────────────────────────────────────
class AgentState(TypedDict):
    # 核心对话
    messages: Annotated[Sequence[BaseMessage], operator.add]

    # 任务计划（DAG 结构）
    task_graph: Optional[TaskGraph]

    # 当前执行上下文
    current_step: Optional[str]
    execution_history: list[StepResult]

    # 内存引用
    memory_context: list[MemoryEntry]

    # 轨迹
    trajectory: list[TrajectoryStep]

    # 人类反馈
    pending_approval: Optional[str]
    human_feedback: Optional[HumanFeedback]

    # 反思状态
    reflection_count: int
    max_reflection: int

# ── Decision-Making Nodes ─────────────────────────────────
def planner_node(state: AgentState) -> AgentState:
    """
    Planner Agent — 核心决策节点

    自主决定：
    - 是否需要搜索知识库？
    - 是否需要 Web 搜索补充信息？
    - 是否需要从记忆检索历史模板？
    - 需要划分多少步骤？
    - 步骤之间的依赖关系是什么？
    - 是否需要用户确认？
    """
    # LLM 自主决策：选择工具 + 构建 TaskGraph
    ...

def tool_execution_node(state: AgentState) -> AgentState:
    """工具执行节点 — Planner 选择的 Tool 在此执行"""
    ...

def coder_node(state: AgentState) -> AgentState:
    """Coder Agent — 将规划步骤转为 JSON 渲染指令"""
    ...

def validator_node(state: AgentState) -> AgentState:
    """Validator Agent — 校验 JSON 结构与逻辑"""
    ...

def reflection_node(state: AgentState) -> AgentState:
    """Reflection Agent — 分析失败原因并调整策略"""
    ...

def human_approval_node(state: AgentState) -> AgentState:
    """人类审批节点 — 中断执行，等待人类反馈"""
    ...

# ── Router (条件边 — Agent 自主决策的核心) ─────────────────
def router(state: AgentState) -> Literal[
    "tool_execution",
    "coder",
    "validator",
    "reflection",
    "human_approval",
    "END"
]:
    """
    核心路由逻辑：Agent 根据当前状态自主决定下一步

    这是 Agent vs Workflow 的关键区别：
    不是固定的 Step1→Step2→Step3
    而是动态决策下一步做什么
    """
    last_message = state["messages"][-1]

    # 如果有 tool_call，执行工具
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tool_execution"

    # 如果 Planner 构建了 TaskGraph，进入 Coder
    if state.get("task_graph") and not state.get("current_step"):
        return "coder"

    # 如果 Coder 完成了当前 Step，进入 Validator
    if state.get("execution_history") and state["execution_history"][-1].status == "coded":
        return "validator"

    # 如果 Validator 失败，进入 Reflection
    if (state.get("execution_history") and
        state["execution_history"][-1].status == "validation_failed" and
        state["reflection_count"] < state["max_reflection"]):
        return "reflection"

    # 如果需要人类审批
    if state.get("pending_approval"):
        return "human_approval"

    return "END"

# ── Graph Construction ─────────────────────────────────────
def build_agent_graph() -> StateGraph:
    workflow = StateGraph(AgentState)

    # 添加节点
    workflow.add_node("planner", planner_node)
    workflow.add_node("tool_execution", ToolNode(ALL_TOOLS))
    workflow.add_node("coder", coder_node)
    workflow.add_node("validator", validator_node)
    workflow.add_node("reflection", reflection_node)
    workflow.add_node("human_approval", human_approval_node)

    # 设置条件边（Agent 自主路由）
    workflow.add_conditional_edges(
        "planner",
        router,
        {
            "tool_execution": "tool_execution",
            "coder": "coder",
            "human_approval": "human_approval",
            "END": END,
        }
    )

    workflow.add_conditional_edges("tool_execution", router, {**route_map, "planner": "planner"})
    workflow.add_conditional_edges("coder", router)
    workflow.add_conditional_edges("validator", router)
    workflow.add_conditional_edges("reflection", router)
    workflow.add_conditional_edges("human_approval", router, {"planner": "planner", "END": END})

    # Planner 为入口
    workflow.set_entry_point("planner")

    return workflow.compile(checkpointer=MemorySaver(), interrupt_before=["human_approval"])
```

### 6.1 设计原则

### 7.2 Memory Manager 核心功能

```python
class MemoryManager:
    """
    记忆管理器 — 管理记忆的全生命周期

    核心职责：
    1. Context Compression — 何时压缩、如何压缩
    2. Reflection-based Extraction — 从失败/成功中抽取经验
    3. Importance Scoring — 哪些记忆值得保留
    4. Memory Decay — 过时记忆的衰减与清理
    5. Memory Retrieval — 高效检索相关记忆
    """

    # ── 配置 ──
    COMPRESSION_TRIGGER_TOKENS: int = 80_000    # 超过此 Token 数触发压缩
    COMPRESSION_TARGET_TOKENS: int = 40_000     # 压缩目标 Token 数
    IMPORTANCE_THRESHOLD: float = 0.6           # 低于此分数的记忆可能被衰减
    DECAY_HALF_LIFE_DAYS: int = 30              # 记忆衰减半衰期
    REFLECTION_TRIGGER: int = 3                 # 连续失败此次数触发 Reflection

    async def compress_context(
        self,
        messages: list[BaseMessage],
        target_tokens: int
    ) -> list[BaseMessage]:
        """
        Context Compression（上下文压缩）

        策略：
        1. 保留最近 K 轮完整对话（高保真窗口）
        2. 对更早的轮次使用 LLM Summarization
        3. 重要决策（TaskGraph 变更、人类反馈）不压缩
        4. Trajectory 保留结构化摘要

        返回压缩后的消息列表
        """
        ...

    async def extract_experience(
        self,
        trajectory: list[TrajectoryStep],
        outcome: ExecutionOutcome
    ) -> list[MemoryEntry]:
        """
        通过 Reflection 从轨迹中抽取经验

        输入：完整的 Thought-Action-Observation 轨迹
        输出：结构化的经验条目

        经验类型：
        - SUCCESS_PATTERN：成功的策略模式
        - FAILURE_PATTERN：失败的模式与根因
        - USER_PREFERENCE：发现的用户偏好
        - STRATEGY_INSIGHT：策略层面的洞察
        """
        ...

    async def calculate_importance(
        self,
        entry: MemoryEntry
    ) -> float:
        """
        重要性评分 (0.0 ~ 1.0)

        评分因子：
        - recency：最近使用时间（越近越高）
        - frequency：使用频率（越高越高）
        - user_feedback：用户评分/采纳率
        - task_success：关联任务的成功率
        - generality：概念的泛化程度
        - uniqueness：与已有记忆的差异度

        加权公式：
        score = 0.25*recency + 0.25*frequency + 0.20*user_feedback
              + 0.15*task_success + 0.10*generality + 0.05*uniqueness
        """
        ...

    async def apply_decay(self) -> int:
        """
        Memory Decay（记忆衰减）

        定期任务（每天执行）：
        1. 对所有记忆计算衰减后的分数
        2. 分数 < IMPORTANCE_THRESHOLD 的记忆标记为 "decayed"
        3. decayed 记忆在 7 天后删除（软删除，可恢复）
        4. 已被后续经验"覆盖"的记忆提前衰减

        衰减公式：score *= 0.5 ^ (days_since_last_access / DECAY_HALF_LIFE_DAYS)
        """
        ...

    async def retrieve(
        self,
        query: str,
        context: AgentState,
        top_k: int = 10,
        filters: Optional[dict] = None
    ) -> list[MemoryEntry]:
        """
        混合检索

        1. 语义检索（pgvector cosine similarity）
        2. 关键词检索（PostgreSQL full-text search）
        3. 图检索（概念关联图谱中的相邻节点）
        4. 融合排序（RRF: Reciprocal Rank Fusion）
        """
        ...

    async def write(
        self,
        entry: MemoryEntry,
        trigger: Literal["reflection", "human_feedback", "auto"]
    ) -> str:
        """
        写入记忆

        写入前检查：
        1. 是否与已有记忆高度重复？（相似度 > 0.95 → 更新而非新增）
        2. 是否是新的有价值信息？（重要性 > IMPORTANCE_THRESHOLD）
        3. 是否需要更新概念关联图谱？
        """
        ...
```

## 8. 反思系统

### 8.1 设计原则

> Reflection 不是简单的 Retry。Retry 是"再来一次"，Reflection 是"为什么失败 → 如何调整 → 再试一种新方法"。

### 8.2 Reflection vs Retry 对比

```
Retry（简单重试）:                       Reflection（智能反思）:

  JSON生成                               JSON生成

  Validator: FAIL                        Validator: FAIL
     │                                      │

  Validator: FAIL                      │  • 缺失字段：3个    │
```

```python
class ReflectionAgent:

    1. 失败根因分析（Root Cause Analysis）
    2. 策略调整建议（Strategy Adjustment）

    async def reflect(
        self,
        state: AgentState,
        failure_context: FailureContext
    ) -> ReflectionResult:
        """
        反思主流程

        输入：
        - state: 完整的 Agent 状态（含轨迹）
        - failure_context: 失败上下文（哪个步骤、什么错误）

        输出：
        - root_cause: 根本原因分类
        - adjusted_strategy: 调整后的策略

        - PLANNING_ERROR：规划本身有问题（步骤顺序/粒度不合适）
        - CODING_ERROR：JSON 结构/逻辑有问题
        - KNOWLEDGE_GAP：知识覆盖不足
        - SCHEMA_VIOLATION：违反 JSON Schema 约束
        - COMPLEXITY_OVERFLOW：生成内容超出模型能力
        - CONTEXT_TRUNCATION：上下文过长导致关键信息丢失
        - TOOL_MISUSE：工具选择或参数错误
        - AMBIGUITY：用户需求模糊导致方向偏差

        """
        策略调整建议

        调整维度：
        1. 降低步骤粒度（拆分复杂步骤）

        """
        抽取经验并写入 Memory

        输出：写入的 memory_id 列表
        """
        ...

    async def meta_evaluate(
        self,

        - 规划粒度是否恰当？
```

### 11.2 反馈类型与处理策略

```python
class FeedbackType(str, Enum):
    PARAM_ADJUSTMENT = "param_adjustment"     # 用户直接修改了参数
    RATING = "rating"                         # 评分（1-5）
    STEP_REORDER = "step_reorder"             # 用户重新排序了步骤
    STEP_ADD = "step_add"                     # 用户添加了步骤
    STEP_REMOVE = "step_remove"               # 用户删除了步骤
    TEXT_FEEDBACK = "text_feedback"           # 文字反馈
    CORRECTION = "correction"                 # 用户纠正了错误
    STYLE_PREFERENCE = "style_preference"     # 风格偏好

class FeedbackProcessor:
    """反馈处理器 — 将人类反馈转化为学习信号"""

    async def process(self, feedback: HumanFeedback) -> LearningSignal:
        match feedback.type:
            case FeedbackType.PARAM_ADJUSTMENT:
                # 用户修改了 duration/color/position 等
                # → 记录到 Memory: user_preference
                # → 下次生成时注入偏好
                return LearningSignal(
                    type="preference_update",
                    key=feedback.target_param,
                    old_value=feedback.old_value,
                    new_value=feedback.new_value,
                    importance=0.7
                )

            case FeedbackType.RATING:
                # 评分 < 3 → 触发 Reflection
                # 评分 >= 4 → 记录成功模式
                if feedback.rating <= 2:
                    return LearningSignal(
                        type="trigger_reflection",
                        reason=f"用户评分过低: {feedback.rating}"
                    )
                else:
                    return LearningSignal(
                        type="success_pattern",
                        pattern=extract_pattern(feedback.context)
                    )

            case FeedbackType.CORRECTION:
                # 用户纠正了知识性错误
                # → 更新知识库（高优先级）
                # → 写入 Memory: failure_pattern
                return LearningSignal(
                    type="knowledge_correction",
                    importance=1.0,
                    content=feedback.correction_content
                )

            case FeedbackType.TEXT_FEEDBACK:
                # 文字反馈 → LLM 解析 + 分类
                parsed = await self.parse_text_feedback(feedback.text)
                return await self.process(parsed)
```

| **部署** | 容器化 | Docker Compose (dev) / K8s (prod) | 标准化部署 |
| | GPU | NVIDIA T4/A10 (vLLM) | 推理加速 |
| | CI/CD | GitHub Actions | 自动化测试 + Benchmark |

### 12.2 为什么选择 LangGraph

| 考量因素 | 分析 |
|----------|------|
| **Agent 循环原生支持** | StateGraph 天然支持 Thought→Action→Observation 循环 |
| **条件路由** | Conditional Edges 实现 Agent 自主决策的 Router |
| **Human-in-the-Loop** | `interrupt()` / `Command` 原生支持中断与恢复 |
| **图结构任务** | Task DAG 是图，LangGraph 是图执行引擎 — 天然匹配 |
| **Streaming** | Native streaming 支持逐帧推演 |
| **生态** | LangSmith 可观测性 + LangServe 部署 + Hub 社区 |
| **企业采纳** | 大厂 Agent 团队广泛使用，面试讨论价值高 |

### 12.3 为什么选择 Java + Spring Boot

| 考量因素 | 分析 |
|----------|------|
| **Virtual Threads（Java 21+）** | Agent 场景有大量 I/O 等待（LLM 调用 3-30s、Tool 执行、DB 查询、gRPC 跨服务通信），传统线程池模型在此场景下极易成为瓶颈。Virtual Threads 提供百万级轻量并发，one-thread-per-task 编程模型简洁直观，同时保持 JVM 在高吞吐场景下的 JIT 编译优势 |
| **Spring AI 生态** | Spring 官方 AI 框架（2025 年 1.0 GA），提供 ChatClient、VectorStore、Agent 抽象、MCP Client 集成。Java 侧可复用 LLM 调用能力做简单推理任务（如渲染指令分类、日志异常检测），复杂 Agent 决策仍走 Python LangGraph |
| **Spring Boot 企业级基础设施** | API Gateway（Spring Cloud Gateway）、流式推流（WebFlux + `Flux<ServerSentEvent>`）、容错（Resilience4j Circuit Breaker）、全链路可观测性（Micrometer + OpenTelemetry Agent，Spring Actuator 开箱即用）——这些是 Python 生态相对薄弱的环节 |
| **GraalVM Native Image** | 将 Spring Boot 应用编译为原生二进制：启动 < 100ms，内存 ~30MB（vs JVM 模式 200MB+），Docker 镜像可精简至 ~50MB。解决了 Java 传统"重"的短板，同时保留 JVM 模式的 JIT 编译性能红利 |
| **Spring Batch 评估 Pipeline** | 文档第 18 节定义的 EduCS-Benchmark 需要批量、可恢复、带重试的大规模 Agent 评估运行。Spring Batch 是该场景的工业标准方案（chunk 处理、失败重试、作业状态持久化） |
| **异构架构的面试价值** | Python（Agent Thinking）+ Java（System Infrastructure）的异构架构是业界 Agent 工程化的主流实践（OpenAI、Anthropic、Google 均采用类似模式）。在面试中能展示跨语言工程判断力和 Agent 系统工程化的完整认知 |
| **社区与人才** | Spring Boot 在全球（尤其国内）拥有最庞大的后端开发者社区和成熟的招聘市场。以 Java 为主技术栈投递"后端+Agent"岗位，匹配度最高 |

```text
你是一个计算机科学教学推演系统的 Planner Agent。

## 核心能力
你可以自主决策教学策略，包括但不限于：
- 将复杂 CS 概念分解为教学步骤
- 构建包含依赖关系和并行分支的 Task DAG
- 选择合适的工具（知识库搜索、Web搜索、记忆检索、人类审批）
- 根据复杂度动态调整教学策略

## 决策框架（ReAct）
对于每个步骤：
1. Thought：分析当前状态和需求
2. Action：选择并调用工具
3. Observation：评估工具返回结果
4. Decision：决定下一步（继续/调整/请求帮助/完成）

## 工具使用原则
- 在生成计划前，总是先查询知识库和记忆

- 如果连续 2 次工具调用未获得有用信息，向用户请求澄清
- 复杂或高风险的计划必须请求人类审批

## TaskGraph 构建原则
- 步骤粒度：每个步骤应在 1-3 分钟内可完成
- 依赖关系：清晰标记前置依赖
- 并行机会：识别可以并行展示的概念
- 可选分支：提供"深入探索"的可选路径
- 难度标注：每个节点标注难度 1-5

## 输出格式
使用工具 build_task_graph 输出结构化的 Task DAG，包含：
- 节点列表（含类型、描述、难度、预估时长）
- 依赖边（含类型：顺序/条件/可选）
- 总体预估耗时

## 质量要求
- 逻辑正确性 > 速度
- 教学清晰度 > 内容密度
- 用户可理解性 > 技术精确性
- 不确定时不猜测，使用工具验证
```

```python
class TrajectoryStep(BaseModel):
    """单步轨迹 — ReAct 循环的一个完整回合"""
    step_index: int
    timestamp: datetime

    # ReAct 三要素
    thought: str                       # Agent 的思考过程
    action: Action                     # 采取的行动
    observation: Observation           # 观察到的结果

    # 元数据
    agent: str                         # 执行此步骤的 Agent
    tool_calls: list[ToolCallRecord]   # 工具调用记录
    llm_call: LLMCallRecord            # LLM 调用记录
    latency_ms: int                    # 本步骤耗时
    token_usage: TokenUsage            # 本步骤 Token 消耗

    # 质量评估
    decision_quality: Optional[float]  # 事后评估的决策质量 (0-1)
    was_optimal: Optional[bool]        # 是否为最优决策路径

class Action(BaseModel):
    type: Literal["tool_call", "agent_delegate", "human_approval", "finish"]
    tool_name: Optional[str]
    params: Optional[dict]
    reasoning: str                     # 为什么采取此行动

class Observation(BaseModel):
    success: bool
    result: Optional[dict]
    error: Optional[str]
```

| "为什么用 Python + Java 异构架构？" | Python 负责 Agent Thinking（LangGraph + LLM 决策），Java 负责 System Infrastructure（Spring Boot + Virtual Threads + Spring AI），各取所长；业界公认的 Agent 系统工程化实践 | ⭐⭐⭐⭐⭐ |
| "Java 在 Agent 系统中能做什么？" | API Gateway（Spring Cloud Gateway）、SSE 流式推流（WebFlux + Virtual Threads）、Sandbox Pool 管理、EduCS-Benchmark 自动化评估 Pipeline（Spring Batch）、全链路可观测性（Micrometer + OTEL） | ⭐⭐⭐⭐⭐ |
| "Virtual Threads 解决了什么问题？" | Agent 场景有大量 I/O 等待（LLM 调用 3-30s、Tool 执行、DB 查询），传统线程池会成为瓶颈；Virtual Threads 百万级轻量并发，one-thread-per-task 模型，代码简洁且吞吐量高 | ⭐⭐⭐⭐⭐ |
| "Spring AI 在你项目中怎么用？" | Spring AI 作为 Java 侧 LLM 调用抽象层（ChatClient、VectorStore），通过 gRPC 桥接 Python Agent Runtime，Java 侧负责可观测性（Micrometer Trace）和流控（Resilience4j） | ⭐⭐⭐⭐ |
| "Agent 延迟怎么优化？" | Streaming 逐帧推演；工具并行调用；GPU 推理优化；Java Virtual Threads + GraalVM Native Image 低延迟路径；Caffeine 缓存策略 | ⭐⭐⭐⭐ |
| "Java 服务和 Python Agent 如何通信？" | gRPC（高性能 Protobuf 序列化，适合大量渲染指令传输）+ Redis Pub-Sub（松耦合事件通知，适合 Agent 状态变更）；根据数据量和实时性要求选协议 | ⭐⭐⭐⭐ |
| "如何处理生产环境的失败？" | 四级降级：Retry → Reflection → Fallback → Human | ⭐⭐⭐⭐ |
