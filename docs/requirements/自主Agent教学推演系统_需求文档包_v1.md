## 1. 文档说明

### 1.1 文档目标

本文档面向开发团队，用于定义一个 Web 形态的自主 Agent 教学推演系统。系统面向本科阶段计算机科学与软件工程教育场景，能够根据用户输入的知识点、教材材料、课件或代码，自动规划教学策略，生成逐帧级交互推演页面，并导出为可由 Manim 渲染的高清视频。

### 1.2 产品一句话

将抽象的 CS 知识点自动转化为可交互、可编辑、可反思优化、可导出高清视频的逐帧教学推演序列。

### 1.3 当前决策

- 首批用户：大学 CS 与软件工程学生、教师。
- 首批内容范围：本科阶段 CS 核心概念。
- 典型输入：自然语言问题、课件/PDF/教材章节/代码、知识点模板。
- MVP 核心输出：可交互逐帧推演页面、Manim 视频导出。
- 推演粒度：逐帧级。
- 教师编辑：MVP 支持。
- Agent 自主性：默认自主规划；教师可选择性约束大纲与风格。
- 反馈闭环：用户反馈与智能体反思模块都需要。
- 产品形态：Web 应用。
- 未来扩展：预留领域插件机制，支持大学多学科与企业演示。
- 暂不纳入 MVP：多人协作、课程班级管理、学生进度管理。

## 2. 产品愿景与定位

### 2.1 产品愿景

成为面向高等教育与专业知识传播的智能教学推演基础设施。它不是普通课件生成器，而是一个能够理解知识结构、规划教学路径、编排多模态资源、生成交互式推演、持续反思优化的 Agent 教学系统。

### 2.2 核心价值

- 对学生：把抽象概念拆解为逐帧状态变化，降低理解门槛。
- 对教师：减少从知识点到动画课件、讲稿、视频的制作成本。
- 对课程团队：沉淀可复用的知识推演资产。
- 对未来跨领域场景：提供可扩展的领域模板、渲染组件和推演 DSL。

### 2.3 产品边界

系统不以在线课堂、班级 LMS、考试系统作为 MVP 核心。MVP 聚焦于“从输入到推演再到视频”的内容生成与编辑闭环。

## 3. 用户画像

### 3.1 学生用户

学生需要在课前预习、课后复习、作业调试、概念攻坚时获得清晰的动态解释。学生关注：

- 是否能看懂每一步发生了什么。
- 是否能修改参数观察结果变化。
- 是否能从错误理解中被纠正。
- 是否能获得题目、总结和复盘。

### 3.2 教师用户

教师需要快速生成可用于课堂展示、在线课程或课程资料的推演内容。教师关注：

- 是否符合课程大纲和授课风格。
- 是否可编辑、可控、可复用。
- 是否能导出高质量视频。
- 是否能保证内容准确性和表达质量。

### 3.3 助教/课程建设者

助教需要批量构建知识点推演资产，并辅助教师修订。助教关注：

- 批量生成与审校效率。
- 内容版本管理。
- 公式、代码、图结构、状态表是否准确。
- 是否方便嵌入课程网站或教学平台。

## 4. 典型场景

### 4.1 自然语言生成推演

用户输入：“讲解 Dijkstra 算法，并用一个包含 6 个节点的带权图逐步演示。”

系统自动生成：

- 教学目标。
- 先修知识提醒。
- 分帧推演脚本。
- 图结构和可调参数。
- 每一帧的状态变化。
- 页面交互控件。
- 可导出的 Manim 脚本与视频。

### 4.2 上传材料生成推演

教师上传课件或教材章节，系统识别知识点、抽取概念结构，生成候选推演主题。教师选择其中一个主题后，系统生成逐帧页面与视频。

### 4.3 代码驱动推演

用户上传或粘贴代码，例如排序算法、内存分配器、线程同步示例。系统解析代码逻辑，生成变量状态、执行路径、关键分支和动画帧。

### 4.4 教师约束生成

教师指定：

- 面向大二学生。
- 用严谨但直观的风格。
- 先讲直觉，再讲伪代码，再演示例子。
- 不使用过度拟人化类比。
- 输出 8 分钟视频。

系统在约束内自主规划教学策略。

### 4.5 反思优化

系统生成初稿后，自动执行事实校验、逐帧连贯性检查、动画可渲染性检查、知识覆盖检查和教学清晰度评估。若发现问题，自动提出修订并生成新版本。

## 5. MVP 范围

### 5.1 MVP 必须支持

- Web 应用基础工作台。
- 三类输入：自然语言、上传材料、知识点模板。
- 本科 CS 核心知识点生成。
- Agent 自主教学规划。
- 教师可选约束。
- 逐帧级推演生成。
- 交互式推演播放器。
- 参数面板。
- 教师编辑器。
- Manim 脚本生成。
- 视频渲染任务与下载。
- 用户反馈入口。
- Agent 反思与质量评估。
- 内容版本保存。

### 5.2 MVP 暂不支持

- 班级、课程空间、作业派发、学生进度追踪。
- 多人实时协作。
- 大规模内容市场。
- 完整 LMS 集成。
- 企业组织权限体系。

### 5.3 MVP 内容优先级

第一批建议覆盖：

- 数据结构：数组、链表、栈、队列、哈希表、堆、二叉树、AVL、红黑树、图。
- 算法：排序、二分、递归、动态规划、贪心、BFS、DFS、Dijkstra、最小生成树。
- 操作系统：进程线程、调度、同步互斥、死锁、分页、缓存、虚拟内存。
- 计算机网络：分层模型、TCP 握手挥手、拥塞控制、路由、DNS、HTTP。
- 数据库：索引、B+ 树、事务、锁、隔离级别、查询执行计划。
- 软件工程：需求分析、架构图、设计模式、测试流程、CI/CD 流程。

## 7. 核心用户流程

### 7.1 创建推演

1. 用户点击新建推演。
2. 选择输入方式：自然语言、上传材料、知识点模板。
3. 填写目标用户、难度、时长、风格、输出形态。
4. 可选设置教师约束。
5. 系统生成教学计划草案。
6. 用户确认或编辑计划。
7. 系统生成逐帧推演。
8. 进入编辑器和预览。

### 7.2 编辑推演

1. 用户查看帧列表。
2. 选择某一帧。
3. 修改画面元素、讲解文本、状态变量、动画动作、参数约束。
4. 点击局部重生成。
5. 系统保留人工修改并重算相关帧。
6. 用户预览结果。

### 7.3 导出视频

1. 用户点击导出视频。
2. 系统生成 Manim 脚本。
3. 执行动画可编译检查。
4. 用户选择分辨率、帧率、旁白、字幕、片头片尾。
5. 提交渲染任务。
6. 渲染完成后下载 MP4、Manim 源码和字幕文件。

### 7.4 反馈与反思

1. 用户在预览页标注问题。
2. 系统将反馈绑定到帧、知识点或整体项目。
3. Agent 分析反馈类型。
4. Agent 生成修订方案。
5. 用户选择接受、部分接受或拒绝。
6. 系统生成新版本并保存差异。

## 8. Agent 能力需求

### 8.1 Agent 总体架构

系统采用多 Agent 协同，但对用户呈现为一个统一助手。

**当前实现（v0.6.0）— 5 个 LangGraph Agent 节点：**

- **教学规划 Agent** (Planner) — 制定教学目标、大纲、策略
- **知识解析 Agent** (Knowledge) — 构建概念关系图、提取关键术语
- **推演编排 Agent** (Coder) — 逐帧生成 DSL（Parameter/Resource 作为其 Tool 调用）
- **质量评估 Agent** (Quality) — 三层校验（Schema + 状态一致性 + LLM 六维度评分）
- **反思修订 Agent** (Reflection) — 根据质量报告修正 DSL，循环上限 3 次

**确定性管线（非 Agent）：**

- **Manim 生成管线** — 作为独立适配器层运行，不参与 LangGraph 编排。提供双路径：
  - LLM 驱动路径（默认）：教学语义 → LLM 自主设计可视化 → Validator 检测 → 自动修复
  - 确定性规则路径（回退）：DSL → 固定 Mobject/Animation 映射

> 设计决策：Manim 代码生成不设为独立 Agent 节点，因为生成过程不需要与其他 Agent 进行状态协商——它从最终 DSL 单向消费数据，在独立线程/Worker 中异步执行。

### 8.2 教学规划 Agent

职责：

- 判断学习者水平。
- 生成教学目标。
- 识别先修知识。
- 选择教学路径。
- 决定讲解顺序。
- 设计概念引入、例子、反例和总结。

输入：

- 用户主题。
- 上传材料。
- 教师约束。
- 目标年级与课程背景。

输出：

- 教学目标列表。
- 知识点大纲。
- 难度曲线。
- 推演策略。
- 内容风险点。

### 8.3 知识解析 Agent

职责：

- 从文本、PDF、课件、代码中抽取知识点。
- 构建概念关系。
- 识别公式、伪代码、状态变量和数据结构。
- 标注容易误解的点。

输出应包含：

- 概念节点。
- 关系边。
- 前置依赖。
- 关键术语。
- 可视化对象候选。
- 可交互参数候选。

### 8.4 推演编排 Agent

职责：

- 将知识点拆成逐帧序列。
- 为每一帧定义画面元素、状态变化、讲解文本和交互逻辑。
- 保证帧间状态一致。
- 生成可映射到前端和 Manim 的中间表示。

每一帧至少包含：

- frame_id。
- title。
- learning_goal。
- narration。
- visual_objects。
- state_snapshot。
- transition_from_previous。
- interaction_hooks。
- validation_rules。

### 8.5 参数设计 Agent

职责：

- 根据知识点生成可调参数。
- 为学生和教师区分参数等级。
- 定义参数取值范围、默认值和边界情况。
- 生成参数改变后的状态重算逻辑。

参数示例：

- 算法类：输入规模、数组内容、图结构、边权、速度、是否显示伪代码。
- 操作系统类：进程数量、时间片、调度策略、页大小、缓存容量。
- 网络类：RTT、窗口大小、丢包率、拓扑结构、拥塞控制算法。
- 数据库类：表规模、索引类型、查询条件、事务并发数、隔离级别。

### 8.6 多模态资源 Agent

职责：

- 生成知识卡片。
- 生成思维导图。
- 生成状态表。
- 生成伪代码区块。
- 生成图、树、表格、时间线、内存布局等可视化资源。
- 为 Manim 和 Web 前端生成共享资源描述。

### 8.7 Manim 生成管线（确定性适配器，非 Agent）

> **实现状态：** v0.6.0 已实现双路径 + Validator + 自动修复 + 容错渲染。

职责：

- 将推演中间表示（DSL）转为 Manim Python 脚本。
- 提供两种生成路径：
  - **LLM 驱动（当前默认）**：将 DSL 帧序列 + 教学计划传给 LLM，由 LLM 自主设计可视化布局、配色方案和动画编排
  - **确定性规则（快速回退）**：DSL 中每种 VisualObject 和 Animation 按固定映射生成对应 Manim 代码
- 对 LLM 生成的脚本执行 6 项静态质量检测（语法/CJK/lexer/API兼容/r-string 转义/调试残留）。
- 自动修复常见 API 问题（`Code(code=…)` → `code_string=…`、移除 Code 上的 font_size、无效 language 降级为 text）。
- 校验失败时将错误反馈给 LLM 重试一次。
- 线程隔离渲染（ThreadPoolExecutor），不阻塞 FastAPI 事件循环。
- 双模式执行：Redis Worker 消费（生产）+ 进程内 fallback（开发/Worker 不可用时）。
- Manim 未产出最终 MP4 时，自动扫描 `partial_movie_files/` 通过 FFmpeg concat 合并分片。

输出：

- main.py（Manim 脚本）。
- render_config.json。
- subtitles.srt。
- output.mp4。

### 8.8 质量评估 Agent

职责：

- 检查事实正确性。
- 检查教学目标覆盖。
- 检查帧间状态一致性。
- 检查交互参数是否有效。
- 检查 Manim 脚本是否可编译。
- 检查表达是否过难、过浅或跳步。

评分维度：

- 正确性。
- 清晰度。
- 连贯性。
- 可交互性。
- 可渲染性。
- 教学完整性。

### 8.9 反思修订 Agent

职责：

- 根据质量报告和用户反馈生成修改计划。
- 对低分片段局部重写。
- 保留教师人工修改。
- 记录每次修订原因。
- 支持一键应用和逐项确认。

## 10. 功能需求

### 10.1 新建推演

用户故事：

作为教师，我希望输入一个知识点或上传课件，系统自动生成可编辑的教学推演。

需求：

- 支持自然语言输入。
- 支持 PDF、PPT、Markdown、纯文本、代码输入。
- 支持从知识点模板开始。
- 支持选择学科、课程、目标年级、难度、时长、语言风格。
- 支持教师约束：必须讲什么、不要讲什么、采用什么例子、输出时长。
- 系统生成教学计划后，用户可确认或编辑。

验收标准：

- 输入“红黑树插入”后，系统能生成教学目标、知识结构和逐帧计划。
- 上传一份数据结构课件后，系统能识别至少 3 个可推演主题。
- 用户编辑教学计划后，后续生成结果应遵守编辑后的计划。

### 10.2 推演编辑器

用户故事：

作为教师，我希望逐帧检查和编辑系统生成的内容，以便用于课堂。

需求：

- 左侧显示帧列表。
- 中间显示当前帧画布。
- 右侧显示属性编辑面板。
- 支持编辑标题、讲解文本、画面对象、状态变量、动画动作。
- 支持局部重生成当前帧或后续帧。
- 支持锁定人工编辑内容。
- 支持版本比较。

验收标准：

- 教师修改某一帧讲解文本后，预览和视频导出均使用新文本。
- 教师锁定某个图结构后，Agent 重生成不得替换该图结构。
- 用户可回退到任一历史版本。

### 10.3 交互式逐帧播放器

用户故事：

作为学生，我希望像播放动画一样逐帧理解知识点，并能修改参数观察变化。

需求：

- 支持播放、暂停、上一帧、下一帧、跳转。
- 支持逐步执行和自动播放。
- 支持速度控制。
- 支持参数面板。
- 支持显示或隐藏伪代码、状态表、知识卡片。
- 支持在关键帧显示提问或小测。
- 支持高亮当前状态变化。

验收标准：

- 对排序算法，播放器能逐帧展示比较、交换和数组状态。
- 修改数组内容后，系统能重新生成对应推演。
- 学生能在同一页面看到画布、解释文本、状态表和参数面板。

### 10.4 参数面板

用户故事：

作为学生或教师，我希望调整关键参数，观察知识点在不同条件下的表现。

需求：

- 参数由 Agent 根据知识点生成。
- 每个参数包含名称、说明、类型、默认值、范围、可见对象、重算影响。
- 参数类型包括数字、字符串、布尔、枚举、数组、图、代码片段、矩阵。
- 支持教师参数和学生参数分级。
- 支持边界案例快捷选项。

验收标准：

- Dijkstra 示例能调整图结构、边权、起点、是否允许负权。
- 操作系统调度示例能调整进程数量、到达时间、执行时间、调度策略。
- 参数非法时系统给出原因和修复建议。

### 10.5 知识卡片

需求：

- 自动生成关键概念卡片。
- 每张卡片包含定义、直观解释、常见误区、公式或伪代码、相关帧。
- 可在播放器中侧边展示。
- 教师可编辑。

验收标准：

- 对 TCP 三次握手，系统生成 SYN、ACK、连接状态等卡片。
- 点击卡片能跳转到相关帧。

### 10.6 思维导图

需求：

- 根据知识解析结果生成概念图。
- 支持概念依赖、过程步骤、对比关系。
- 支持从思维导图节点跳转到推演帧。
- 支持作为视频总结段落导出。

验收标准：

- 对虚拟内存主题，导图应包含地址转换、页表、TLB、缺页中断、置换算法。

### 10.7 Manim 导出

用户故事：

作为教师，我希望将交互推演导出为高质量教学视频。

需求：

- 从推演 DSL 生成 Manim 脚本（LLM 驱动生成，教学语义 → 可视化设计）。
- 对生成脚本执行 6 项静态质量检测（语法/CJK/lexer/API兼容/r-string 转义/调试残留）。
- 常见 API 问题自动修复（`Code(code=…)` → `code_string=…`、font_size 移除、无效 language 降级）。
- 校验失败时自动将错误反馈给 LLM，重试一次。
- 支持 480p、720p、1080p、4K 画质配置。
- 支持帧率选择（1-120 FPS，服务端校验）。
- 支持字幕开关。
- 支持双模式渲染：Redis Worker 队列（生产）+ 进程内 fallback（开发）。
- 渲染进度实时轮询（Redis 状态 + DB 持久化）。
- Manim 未自动合并时，FFmpeg concat 分片 fallback。
- 支持在线视频预览 + 产物下载（MP4、Manim 源码 .py、字幕 .srt）。

验收标准：

- 用户点击导出后，系统能生成可运行的 Manim 工程。
- 渲染失败时，系统展示错误原因和修复建议。
- 至少对排序、图算法、操作系统调度三类主题完成端到端视频导出。

### 10.8 生成方式可选化（v1.0 规划中）

用户故事：

作为教师，我希望在教学计划审批后，根据实际需求选择需要的产出形式，而不是每次都必须生成完整的逐帧推演。

需求：

- 教学计划审批通过后，提供产出方式选择界面。
- 可选产出组合包括：
  - **思维导图 + 知识卡片**：快速获得知识结构和概念摘要，适合课前预习材料。
  - **完整逐帧推演**：完整的 DSL 帧序列 + Web 交互播放器。
  - **视频导出**：直接生成 Manim 教学视频（可选择画质、帧率、字幕）。
  - **组合模式**：可多选，系统按需生成所选类型。
- 不同产出共享同一份教学计划和知识图谱，避免重复规划。
- 后续可增量添加新产出类型（如仅生成互动 Quiz 测验）。

验收标准：

- 教学计划审批后，用户可选择"仅思维导图 + 知识卡片"，系统生成后不再继续生成逐帧推演。
- 用户可选择"完整推演 + 视频导出"，系统依次生成 DSL 和 MP4。
- 切换产出选择后，已生成的内容不被清除，可继续追加生成。

### 10.9 质量评估与反思

需求：

- 每次生成后自动运行质量评估。
- 输出评分和问题列表。
- 支持一键优化。
- 支持用户反馈驱动修订。
- 支持记录反思链路，但不向普通用户暴露冗长内部推理。

质量问题类型：

- 知识错误。
- 缺少前置解释。
- 跳步。
- 帧间状态不一致。
- 参数无效。
- 动画无法渲染。
- 文案不适合目标学生。

验收标准：

- 若红黑树旋转方向生成错误，质量评估应能标记高风险。
- 若某帧状态变量与上一帧不一致，应阻止直接导出视频。
- 用户反馈“这一步太快”后，系统能插入补充帧。

## 13. 系统架构建议

### 13.1 前端

建议技术：

- React 或 Vue。
- Canvas/SVG/WebGL 混合渲染。
- 状态管理使用 Zustand、Redux Toolkit 或 Pinia。
- 复杂图结构可使用 Cytoscape、D3 或自研渲染层。
- 代码展示使用 Monaco Editor。

### 13.2 后端

建议技术：

- Python FastAPI 或 Node.js NestJS。
- Agent 编排服务。
- 文档解析服务。
- 推演 DSL 服务。
- 渲染任务服务。
- 文件存储服务。

### 13.3 渲染服务

建议：

- 独立 Manim Worker。
- 任务队列使用 Celery/RQ/BullMQ。
- 支持容器化隔离。
- 输出文件上传至对象存储。
- 保留渲染日志和中间帧。

### 13.4 数据存储

建议：

- PostgreSQL：项目、帧、版本、任务。
- Redis：队列、缓存、任务状态。
- 对象存储：上传材料、渲染产物、资源文件。
- 向量库：知识材料检索、历史案例检索。

### 13.5 Agent 编排

建议：

- 使用可观测的工作流编排。
- 每个 Agent 输出结构化 JSON。
- 关键节点必须做 schema 校验。
- 生成结果进入 DSL，不直接驱动前端或 Manim。
- 支持失败重试和局部重生成。

## 14. 非功能需求

### 14.1 性能

- 普通知识点首轮计划生成应在 30 秒内返回。
- 普通推演项目逐帧生成应在 2 分钟内完成。
- 编辑器切换帧响应时间小于 300 毫秒。
- 参数重算应优先支持局部重算，避免全量生成。

### 14.2 稳定性

- Agent 输出必须经过 schema 校验。
- Manim 渲染失败不能导致项目损坏。
- 每次关键生成都保存版本。
- 渲染任务支持重试。

### 14.3 安全

- 上传文件需要类型和大小限制。
- 执行用户代码时必须沙箱隔离。
- Manim 渲染环境必须隔离。
- 不允许生成危险系统命令。
- 教学内容应避免版权和隐私泄露。

### 14.4 可扩展性

- 学科能力通过领域插件扩展。
- 可视化对象通过组件注册机制扩展。
- Manim 模板通过模板库扩展。
- 参数生成策略可按知识点类型扩展。

## 19. 风险与对策

### 19.1 Agent 生成不稳定

对策：

- 使用结构化 DSL。
- 对每个 Agent 输出做 schema 校验。
- 对核心知识点提供模板和规则兜底。

### 19.2 Manim 脚本难以稳定生成

> **当前状态：** ⚡ 已实施多项对策，风险已显著降低。

已实施对策 ✅：

- 先生成 DSL，再由 LLM 根据教学语义生成可视化脚本（v0.6 默认路径）。
- 确定性规则转换器作为快速回退路径。
- Validator 6 项静态检测（语法/CJK/lexer/API兼容/r-string 转义/print 调试残留）。
- 自动修复常见 API 问题（`code=` → `code_string=`、font_size 移除、无效 language 降级）。
- 校验失败时自动将错误反馈给 LLM 重试一次。
- LLM 调用内置 120s 超时 + 4 次 token 递增重试（防止无限循环）。
- Manim 渲染失败不阻塞 Web 交互（独立线程/Docker Worker 隔离）。

仍有空间的对策：

- 建立 Manim 模板库（常见可视化模式的预制代码片段）。
- 对高风险知识点（如 AVL 旋转、红黑树变色）建立专用校验规则。

### 19.3 参数重算复杂

对策：

- MVP 优先支持模板化知识点的参数重算。
- 对通用生成内容提供局部重生成。
- 将参数影响范围显式写入 DSL。

### 19.4 教学质量难评估

对策：

- 结合规则检查、模型评审和用户反馈。
- 将阻塞型问题和建议型问题分级。
- 对高风险知识点建立专用校验器。
